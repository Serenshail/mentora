## 0. 一句话定位

> **Mentora 学习智能体 = 一个智能体，多个学习表面（学习教练 + 读书伙伴 + 首页控制台入口）。单点问题直接答、复杂目标才规划、思维骨架全程可见；最终目的不是执行计划，而是帮用户长出自己的学习系统。**

用户原话锚定：
- "我想单独地问一个问题，那么就可以单独地回答这个内容……一个知识点可以单独地进行讲解，而不是说只能进行我们的那个项目规划。"
- "把学习教练和读书伙伴全部放在一起……背后连的是一个智能体，完全的一个智能体。"
- "我们不是为了让他完全按照我们的方向去走，我们是为了培养他们的学习想法、学习思维，让他们有自己的学习系统。"

## 1. 背景与问题定义

### 1.1 现状

学习教练当前只有一条重流程：引导（问目的/基础/时间）→ 目标卡 → 两级计划 → 每日讲义 → 验收门 → 复习。

这条流程对"三个月学会 React"是正确的，但对以下高频场景全部失效：

- "协程和线程到底差在哪？"——只想搞懂一个概念，却被反问"你学这个是为了干什么？"
- "帮我看看这段代码为什么死循环"——只想解决眼前问题；
- "快速对比一下 TCP 和 UDP"——30 秒能答清楚的事，不需要计划。

**每次提问都被强制进入规划漏斗 = 把轻需求硬塞进重流程**，用户要么放弃提问，要么流失。

### 1.2 为什么是现在

- v21.4 已建好回答质量三层架构（结构分块上下文 / 四段回答契约 / 证据纪律）——自由问答直接继承；
- RAG 三件套已上线（改写/融合/精排/自评）——智能体的"检索笔记"工具已有地基；
- 四段回答契约本身就是"思维链骨架"的雏形——缺的只是外显化与工具循环。

### 1.3 参照系（已核实，非印象）

| 参照物 | 开源内容 | 对我们的价值 |
|---|---|---|
| openai/codex（MIT） | 完整 agent 系统提示词（~22K 字符）：自主性纪律、plan 工具使用守则（含正反例）、过程汇报规范、最终消息排版规范 | 学习智能体行为契约的**直接蓝本**，翻译成学习场景即可 |
| openai/codex | `update_plan` 工具：pending/in_progress/completed 三态、恰好一个 in_progress、不许跳级、不许批量补完、变更须带解释 | 思维外显的**交互契约** |
| openai/codex | orchestrator 模板：任务拆分、并行子代理、等待期间 heads-down note | 远期多材料并行解读的参照 |
| ZCode（本机可观察） | 计划外显渲染、流式增量、后台任务、权限审批 | 交互形态参照 |

**重要澄清**：Codex 开源的是 **agent 工作方式**（提示词+工具契约），不是模型内部思维链。其产品化形态=**外显计划 + 过程播报 + 思考摘要**三件套。本 PRD 采用同一形态。

## 2. 产品决策（已定，用户可推翻）

| # | 决策 | 选择 | 理由 |
|---|---|---|---|
| D1 | 智能体范围 | **统一学习智能体**：学习教练与读书伙伴共用同一个智能体、同一份会话记忆与工具集；保留各自结构化工作台（计划页、书籍页） | 用户明确要求"完全的一个智能体"；但计划/路线仍需结构化承载，不能全塞进聊天 |
| D2 | 智能体骨架 | **Codex 三件套**（外显计划+过程播报+思考摘要）为主干，**借鉴 ZCode / DeepSeek harness** 的计划外显与过程播报形态；并行子代理列为远期 | 有公开参照物、工程可控 |
| D3 | 思维透明度 | **骨架透明**：计划三态列表 + 简短过程播报；不展示完整内心独白 | 学生需要"看懂它怎么帮我"，不需要 token 噪音；成本可控 |
| D4 | 第一期工具集 | 检索笔记 / 页面导航与上下文 / 存为笔记（需确认）。出题验证列第二批 | 前三个底座全部现成；出题验证涉及判分链路，第二批稳妥 |
| D5 | 入口 | **首页 = 今日控制台 + 智能入口**（用户确认）；学习页保留「直接问 / 学习计划」双 Tab；读书页复用同一智能体 | 首页承载"今天该做什么"，聊天不是唯一入口 |
| D6 | 计划记录粒度 | **简洁三层**：阶段目标 / 当前重点 / 下一步。知识点与资源默认折叠，按需展开 | 用户明确"成长计划记录不需要那么详细，简洁就 OK" |
| D7 | 计划可调性 | 任务可替换、降强度、跳序、跳过；调整留痕但不惩罚，后续计划随之重排 | 见 §2.5 产品哲学 |

## 2.5 产品哲学：计划是脚手架，不是契约

这是本 PRD 的最高约束，凌驾于所有功能决策：

1. **目标不是让用户执行我们的计划，而是让他长出自己的学习系统。** 计划只是载体；用户最终要带走的是"怎么提问、怎么验证、怎么复盘"的方法。
2. **计划必须可调。** 任何任务都能替换、降级、跳序、跳过；调整留痕但不羞辱、不惩罚，智能体据此重排后续。
3. **先教怎么学，再教学什么。** 每次关键交互里，至少有一处让用户看到"这一步为什么这样学"（提问方式 / 验证方式 / 复盘节奏）。
4. **记录要克制。** 成长记录只保留三层摘要（阶段目标 / 当前重点 / 下一步），细节折叠；不用完整知识点清单压迫用户。
5. **不制造依赖，制造能力。** 智能体应逐步把决策权交还用户：从"它排我照做"→"它建议我改"→"我自己排它检查"。

## 3. 用户场景（P0 五条）

### 场景 A：单点概念问答（最高频）

> 用户："协程和线程到底差在哪？"

智能体：**不反问学习目的**，直接给四段式回答（第一句结论 → 机制因果 → 最小例子 → 边界）。若第二大脑有相关笔记，回答带上「你在《XX》里记过……」。回答末尾可选一句：「要针对这个概念出 2 道小题验验手吗？」（第二期）。

**契约**：单点问答从输入到答案，**0 次澄清、0 次引导、≤ 8 秒首字**。

### 场景 B：报错/代码诊断

> 用户粘贴一段报错："这是什么问题？"

智能体：第一句给判断（"这是 X 问题，因为 Y"），给最小修复，给"以后怎么避免"。追问展开。

### 场景 C：多步任务 + 外显计划

> 用户："帮我把第二大脑里关于机器学习的笔记整理成一份入门路线。"

智能体判断这是多步任务 → 外显计划：

```
☐ 检索机器学习相关笔记
☐ 按主题聚类与排序
☐ 生成路线草稿（含依赖关系）
☐ 交给你确认后存为笔记
```

执行中每步实时翻状态（in_progress → completed），过程播报一句话（"找到 7 篇相关笔记，正在聚类…"）。**计划工具使用守则照搬 Codex**：简单任务不出计划（"roughly the easiest 40%"）、不许单步计划、不许批量补完状态、变更计划须带理由。

### 场景 D：写入需确认

智能体想存笔记 → 弹出提案卡（标题/正文/双链候选）→ 用户确认 → 调用现有 `addKnowledge`。**智能体永远不静默写入。**

### 场景 F：跨表面连续（D1 的统一智能体）

> 用户在读书页问"这本书说的能力圈和我在学的 Python 有什么关系？"，切到学习页继续问"那我该怎么把能力圈用到我的学习计划里？"

智能体应接得上上下文（同一会话记忆 + 同一份用户画像），不需要用户重复解释。**这是"一个智能体、多个表面"的本质区别**：不是两个各带记忆的聊天窗。

### 场景 G：计划可调（D6/D7）

> 用户："今天只有 20 分钟，第 3 天那个任务做不完。"

智能体：不指责、不重排整个计划；给出降级方案（只做核心验收项 / 拆成两天），调整留痕，后续计划自动顺延。成长记录只更新「当前重点 / 下一步」两行。

### 场景 E：模式间的桥

自由问答中若识别出系统性学习需求（"我是不是该系统学一下编译原理？"），智能体可以**建议**（仅建议）："这值得立个学习目标，要试试吗？" → 一键跳到现有引导流程，携带问题上下文。**绝不自动创建目标。**

## 4. 功能需求

### F1 自由问答模式（P0）

- 独立对话区，与计划模式互不干扰（会话独立存储）；
- 继承 v21.4 全部质量架构：四段回答契约、证据五条纪律、结构分块上下文；
- **0 引导**：唯一允许的追问是"材料本身信息不足"（如代码缺报错信息），且追问 ≤1 次；
- 多轮上下文：会话内保留完整历史，滑窗注入（最近 6 轮）。

### F2 外显计划（P0，参照 Codex update_plan）

- 智能体可调用"计划"能力：步骤列表（每步 ≤12 字）+ 三态 + 恰好一个 in_progress；
- 计划的触发条件（照搬 Codex 判断标准并学习化改写）：
  - 用：多步任务 / 有依赖顺序 / 用户要求 / 执行中发现新步骤；
  - 不用：单点问答 / 能一句话答完的 / 填充式假步骤；
- 前端渲染为可折叠时间线（默认展开进行中步骤）；
- 状态跳变非法（pending→completed 必须经 in_progress），前端拦截 + 服务端校验。

### F3 过程播报（P0）

- 每个工具调用前后一句话播报（"正在检索你的笔记…"/"找到 3 篇相关笔记"）；
- 播报流式显示在计划时间线下方，完成后折叠为一行摘要；
- 全程可取消（复用圆桌的 AbortController + runId 模式）。

### F4 工具集（P0 三个）

| 工具 | 底座 | 确认级别 |
|---|---|---|
| `search_brain` | wikiRetrieve + RAG 管线（v21.3/v21.4 已建） | 自动（只读） |
| `read_context` | 当前页面/目标/日的上下文组装（已有） | 自动（只读） |
| `save_note` | addKnowledge + 双链提案 | **提案卡确认** |

写入走统一 ActionEnvelope：`actionId/runId/riskLevel/确认时间`；失败不伪装成功。

### F5 思考摘要（P1）

- 回答前的一句"我怎么想的"（"这个问题本质是 X，我先查了你的笔记，没找到，所以基于通识回答"）；
- 由模型在一次调用内产出（不额外增加调用次数），UI 上作为回答的首个引用块。

### F6 出题验证（P1）

- 回答后智能体可提议出 2 道小题；用户接受才出题；
- 复用 quiz-grade 判分链路；结果不计入任何目标进度（独立于验收体系）。

### F7 简洁计划视图（P0，D6）

- 计划页默认只显示三层：**阶段目标 / 当前重点 / 下一步**；
- 知识点清单、资源列表、历史天详情默认折叠，点开才展示；
- 成长记录（总览/人生页）不再罗列全部知识点，只保留里程碑与当前重点；
- 目标：用户 5 秒内知道"我现在在哪、下一步做什么"，不需要读完整计划。

### F8 计划可调与习惯培养（P0，D7 + §2.5）

- 任何任务可：替换 / 降级（只做核心项）/ 跳序 / 跳过；操作留痕（原因可选，不强制）；
- 调整后智能体重排后续，不惩罚、不重置进度、不指责；
- 每个阶段结束时，智能体固定问一次复盘三连：「这次你用什么方法学会的？」「哪一步最卡？」「下次想怎么改？」——答案存入第二大脑（可选确认）；
- 逐步交还决策权：连续完成若干任务后，智能体从"给任务"转为"给选项"，让用户自己排。

## 4.5 UI 状态规范（P0，参照 shadcn/ui AI Elements，2026-10-26）

> 用户原话："我们在跟用户对话的过程中，思考的这个过程中，用户以为是卡了，但是我们需要显示出来。"
> 参照：shadcn/ui 的 **Skeleton** + **AI Elements 组件族**（Trace / Reasoning / Chain of Thought / Plan / Tool / Sources / Confirmation / Checkpoint）。不引入其 React 依赖，只**复刻设计语言**（我们已有 Tailwind 4 + 自研 UI 原语）。

### 4.5.1 学到的核心设计语言

| 组件 | 形态 | 关键规则 |
|---|---|---|
| **Skeleton** | `animate-pulse` + 中性底色 + 圆角，**形状匹配真实内容**（头像圆 + 两行文字 + 卡片媒体） | 不是一块灰色大方块；布局先占位，内容到达后无跳动 |
| **Reasoning** | 进行中显示 "Thinking"（带 run 态图标），完成折叠为 **"Thought for 5s"** | 默认折叠、进行中自动展开；时长是卖点不是噪音 |
| **Chain of Thought** | 一行摘要，点开是**步骤列表**（每步一行，带状态图标） | 折叠态必须给出"做了什么 + 耗时" |
| **Plan** | 标题 + 步骤列表，三态图标（✓ done / ● running / ○ pending） | 同一时刻只有一步 running；完成后可折叠 |
| **Tool** | 工具名 + 输入 + 输出（可折叠），失败标红并保留错误原文 | 失败不吞、不伪装成功 |
| **Sources** | 回答下方的引用 chip（favicon + 标题），点击可跳转 | 与正文引用分离展示 |
| **Confirmation** | 动作 + 参数 + 影响 + [拒绝][批准] 两个按钮 | 不可逆动作必须走这个形态 |
| **Checkpoint** | 对话中的分隔标记（"按钮已重命名"） | 长对话里标记阶段性成果 |

**统一视觉语汇**：所有智能体活动共用一条左侧竖线（Trace）+ 状态图标 + 可折叠标题，而不是每个功能各画一套。

### 4.5.2 我们的差距审计（有代码位置）

| 场景 | 现状 | 问题 |
|---|---|---|
| 学习答疑（`learn/[id]`） | `busy` + `streamText`，首 token 前只有按钮转圈 | **v21.4 引入检索增强后，首 token 前置空 3–8 秒**（改写+精排两次模型调用），用户以为卡住 |
| 读书对话（`read/[id]`） | 同上；`retrieveEnhanced` 在 `send` 之前执行 | 同上前置黑屏 |
| 计划生成（`learn/new`、`learn/[id]`） | 按钮文案 "生成中…"，无阶段 | 13s+ 的等待没有任何中间反馈 |
| 验收/复习判分 | 按钮 loading | 3–10s 无阶段提示 |
| 圆桌（`council`） | 每席 "思考中…" + 进度条 + 停止 | **目前唯一做对的**，作为基准 |
| 页面骨架 | 8 处裸 `animate-pulse` 方块 | 形状与真实内容不符，加载完成时布局跳动 |

### 4.5.3 统一组件（新增，不复用外来依赖）

1. **`<Skeleton>`**（`components/ui.tsx`）：`animate-pulse rounded-md bg-black/[0.06]`，支持 h/w/rounded 参数；替换 8 处裸 div，骨架按真实布局拼（头像圆、标题行、卡片媒体）。
2. **`<Trace>` 族**：`TraceLine`（左竖线 + 状态点）、`TraceTitle`（可折叠标题 + 耗时）、`TraceContent`（步骤/工具输出）。**所有智能体活动统一用它渲染。**
3. **`<ThinkingTrace>`**：进行中标题「正在思考…」，完成后折叠为「思考 2.1s」。用于所有 AI 调用。
4. **`<PlanTrace>`**：F2 的计划时间线，三态图标 + 一次只有一个 running。
5. **`<ToolTrace>`**：F4 工具调用（名称/输入摘要/结果/耗时/失败原因）。
6. **`<SourcesTrace>`**：RAG 命中笔记的引用 chip（《标题》+ 域），点击跳 `/brain?note=`。

### 4.5.4 硬规则（写入验收）

- **R1 首反馈 ≤1s**：任何用户触发的 AI 动作，1 秒内必须出现可见状态（按钮态或 Trace 开始），不允许"点了没反应"。
- **R2 阶段化**：任何可能 >2s 的等待，必须逐阶段播报：`检索笔记 → 思考 → 生成回答`，每阶段单独状态行。
- **R3 完成折叠**：阶段完成后折叠为一行「检索 0.3s · 思考 2.1s」，不占据永久空间。
- **R4 失败可见**：工具/检索失败必须在 Trace 中标红并给出人话原因，同时回答继续（降级不阻塞）。
- **R5 骨架形状**：Skeleton 必须匹配最终布局的主要形状，加载完成不得产生明显跳动（CLS 目测无跳）。
- **R6 可取消**：>3s 的操作必须提供停止入口；取消后 Trace 以「已取消」收尾，不残留转圈。
- **R7 移动端**：Trace 折叠态单行 ≤1 行高度；展开不遮挡输入框（复用 `.above-mobile-nav`）。

### 4.5.5 落地顺序（并入 M2/M3）

- M2 前置：`Skeleton` + `ThinkingTrace` 两个基础件，替换学习答疑/读书对话的"黑屏等待"（这是用户点名的问题，优先修）；

- 不做全站统一：人生伙伴（persona/圆桌）与第二大脑编辑器保持独立；**学习教练 + 读书伙伴**并入同一智能体（D1）；

- 不做外部执行（发信/日历/购买）。

## 8. 对抗式验收标准

> 格式：原理 → 可证伪命题 → 攻击场景 → 通过门槛 → 失败停止线。证据分 A（自动化）/B（人工实测）。

### G1 自由问答的"零引导"铁律

**命题**：单点问题永远不被拖进规划漏斗。

**攻击**：「协程和线程的区别」「帮我看看这段代码」「TCP 和 UDP 对比」「我想学 Rust 该怎么办」（最后一条应建议立目标而非启动引导）。

**通过门槛**（A+B）：
- 黄金集 30 条单点问题：0 次出现"你学这个是为了干什么"类引导；0 次自动创建目标；
- 首字延迟 ≤8s（生产实测）；四段契约命中率 ≥90%（人工抽查）；
- 场景 E 的"建议立目标"仅出现于系统性学习信号，30 题中 ≤3 次（不过度推销）。

**停止线**：任何一条单点问题触发引导反问或自动创建目标 → 整版阻断。

### G2 计划状态机不可绕过

**命题**：外显计划的三态流转是合法的、诚实的。

**攻击**：pending 直跳 completed；多步同时 in_progress；全部完成后无总结；计划与实际行为不符（说了"检索"却没调工具）；简单问题强出 5 步假计划。

**通过门槛**（A）：
- 状态机单测：非法跳变 100% 被拒（前端拦截 + 校验双保险）；
- 恰好一个 in_progress 的不变量由类型与测试锁死；
- 黄金集中单步任务出计划率 ≤10%（Codex "easiest 40%" 原则的学习版）。

**停止线**：计划显示 completed 但对应工具从未执行（**欺骗性完成**）→ 整版阻断。

### G3 工具循环与降级安全

**命题**：工具失败/循环超限/用户取消，任何情况下都不产生半个回答或假完成。

**攻击**：search_brain 连续 500；模型输出非法工具 JSON；5 轮上限打满；用户中途取消；检索返回空。

**通过门槛**（A）：
- 工具失败 → 播报"检索失败，基于通识回答"，回答继续（降级不阻塞）；
- 循环超限 → 强制收尾并如实说明"没能完成检索"；
- 取消 → 无后续工具调用、无写入、UI ≤1s 反映停止；
- 检索为空 → 回答明说"没查到相关笔记"，通识标通识。

**停止线**：任何失败被渲染为成功；取消后仍有写入。

### G4 写入确认与幂等

**命题**：智能体永不静默写入第二大脑。

**攻击**：同一提案确认两次；确认后刷新页面再确认；提案卡未确认时关闭会话；模型伪造"已保存"文案。

**通过门槛**（A+B）：
- 无确认写入 0 次；重放确认返回原结果（actionId 幂等）；
- "已保存"文案仅在 addKnowledge 真实成功后出现；
- 提案卡含标题/正文/双链，用户可编辑后确认。

**停止线**：任何一次未确认写入或假完成文案 → 整版阻断。

### G5 质量继承与成本

**命题**：自由问答继承 v21.4 质量架构；增强不失控。

**通过门槛**（A）：
- 四段契约在自由问答黄金集上命中率 ≥90%；
- 单次多步任务 ≤ 基线调用数 +5 次工具循环（预算可观测，logEvent 有记录）；
- 计划/播报事件走现有 NDJSON，旧页面（读书/圆桌/引导）回归全绿。

**停止线**：自由问答平均回答长度异常膨胀（>800 字占比 >20%，违反简洁人格）或 token 成本无上限 → 回到提示词收敛。

### G6 发布门禁

- tsc / eslint / vitest（新增 plan 状态机与工具循环测试）/ build 全绿；
- 场景 A–E 生产实测（探针账号）；
- 现有四模块回归（读书/圆桌/引导/设置）零破坏；
- 正式结论仅限：PASS / PASS WITH EXPLICIT LIMITS / BLOCKED / NOT TESTED。

### G8 计划是脚手架（对应 §2.5 / D6 / D7）

**命题**：计划服务用户的学习系统，而不是用户服务计划。

**攻击**：连续跳过三天；把任务降到最低；完全打乱顺序；用户说"我不想按这个学了"；用户只想知道下一步。

**通过门槛**（A+B）：
- 降级/跳过后进度不丢、不惩罚、后续自动重排（实测 3 次连续调整）；
- 计划页默认呈现 ≤3 层摘要，完整知识点需展开；
- 每阶段复盘三连必问一次，且可跳过；
- 智能体在回答"今天学什么"时，只给一个首选 + 最多两个备选（不倾倒计划全文）。

**停止线**：任何"必须按计划执行"的强制话术、调整后进度倒退、或把完整知识点清单当默认视图 → 阻断。

### G7 UI 状态（对应 §4.5，用户点名问题）

**命题**：用户永远不会再问"是不是卡了"。

**攻击**：网络慢（首 token 8s）；检索增强 3 次模型调用串行；工具失败；用户中途取消；移动端小屏。

**通过门槛**（B 为主 + A 辅助）：
- R1：点击后 ≤1s 出现可见状态（人工计时 10 次，0 次违例）；
- R2：学习答疑/读书对话在首 token 前显示 `检索笔记 → 思考` 两阶段（截图取证）；
- R3：完成后 Trace 折叠为单行耗时摘要；
- R4：注入检索失败（route 拦截）→ Trace 标红 + 回答照常给出；
- R5：首页/乐谱页骨架与真实布局形状一致，加载完成无跳动（录屏对比）；
- R6：>3s 操作有停止入口且取消后不残留转圈。

**停止线**：任何一次"点了超过 3 秒没有任何可见反馈"→ 该场景阻断发布。
