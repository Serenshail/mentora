## 2. 真实持久化验证（不使用 setState 注入）

方法：注册真实账号 → 通过产品 store 动作写入 → 轮询 `/api/sync` 确认云端落库 → **刷新页面且不重新注入** → 校验内存与定位。

| 检查项 | 结果 | 说明 |
|---|---|---|
| 云端快照包含该笔记 | **PASS** | `GET /api/sync` 返回 `{data:{knowledge:[...]}}` 中确认存在该笔记（含正文） |
| 深链会话刷新后仍定位 | **PASS** | 真实创建的会话，`?session=<id>` 首次与刷新后均正确显示议题 |
| 笔记正文刷新后恢复 | **未通过（环境不稳定）** | 见 §2.3 |

### 2.3 笔记刷新恢复未通过的调查

- 现象：刷新后 store 中笔记存在但 `body` 为空（`found=true bodyLen=0`），云端却有正文。
- 已排除：接口契约读错（已修正为 `{data:...}`）、断言过早（已加 25s 轮询）。
- dev 日志显示 `POST /api/sync` 与 `GET /api/sync` **全部 200**，但耗时 **1.3–5.3s**；同一脚本连续运行结果不稳定（一次 2/3、一次 1/3）。
- **结论边界：** 现有证据**不足以判定是产品缺陷还是环境慢导致的时序问题**。已记录「同步慢（1.3–5.3s）」这一事实；笔记正文刷新恢复需在稳定环境下单独复现，**不归为脚本问题**。
