# 全站智能体能力清单

日期：2026-11-09 · 版本：0.1 · 与 PRD 的 AG-01～AG-09 配套

## 1. 口径

本表将用户“智能体能直接操作整个网站”的目标拆成业务动作组。当前状态来自工具注册表、执行器、状态方法及页面针对性阅读，**不是运行成功报告**。

- **已接通：** 在当前工具表和执行器中存在相应入口，仍需运行验收。
- **部分接通：** 只覆盖创建、摘要、跳转或部分字段，不等于整组能力完成。
- **未见接通：** 当前首页工具表未提供相应动作；页面可能已经能做。
- **受控流程：** 智能体协助解释、准备和定位；必要身份验证或最终操作由用户在专用流程完成。

“执行”通过业务动作完成，不要求模拟鼠标点击。页面按钮与智能体应共享业务规则和校验。工具调用次数不是完成度；必须检查对象状态和可见结果。

## 7. 动作统一约定

每个实际执行动作都需要确定：对象、输入、前置状态、权限、变更范围、用户意图、结果、失败方式、是否可恢复。简单明确动作不加无意义的多层确认；未知对象、范围不清或不可逆影响需先澄清/展示影响。

生成建议与持久化必须分开计量。例如生成了新阶段目录但未应用，结果只能是“方案已准备”；本机应用完成但同步失败，不能写“所有设备已更新”。

动作成功的证据至少包括对象 ID、变更摘要、实际结果状态与可打开入口。复合任务逐项报告，未覆盖的天/章节/会话不能省略。

## 8. 全站覆盖的最终验收方法

本表是初始动作组清单，不是已经穷尽所有按钮的声明。进入技术方案前逐页走查每个用户可用动作，将其映射到本表；缺项增行。所有动作标记为直接执行、受控流程或确实无业务写入的纯浏览动作。

覆盖率 = 已通过运行验收的直接执行业务动作数 ÷ 冻结范围内应直接执行的业务动作总数。每个动作必须有用例和证据。受控流程单独报完成率；只返回链接、工具已注册、模型声称成功均不计入执行完成。

不能通过删掉难实现的动作提高覆盖率。新增范围、后移批次或暂缓都记录原因和产品决定。网站“整体打磨完成”要求 P0/P1 全部通过，不等于第一批学习修改流程通过。
