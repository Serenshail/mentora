## 第一部分：批次 D 两项补充

### 1.1 结果入口直达对应会话

- council 页新增 `?session=<id>` 深链：惰性初始化读取并自动选中该会话（目标不存在则回退默认流程；不在 effect 里同步 setState，避免级联渲染）。
- 所有会话相关工具结果文案改为深链：`get_session`、`resume_workflow`（council 分支）、`create_session`、`run_discussion` 均返回 `/council?session=<id>（打开即自动选中…）`。

### 1.2 重复批准验证（并发互斥 ≠ 幂等）

`executeAction` 增加执行幂等守卫：动作 id 执行前登记，**执行中与执行完成后重复提交同一动作都返回「已执行过」**——不重复调用模型、不追加问题、不保存纪要。重试失败部分是**新的审批动作（新 id）**，不受影响。

验证（`council-engine.test.ts` 新增 2 项）：
- 执行中重复提交 → 拒绝；模型调用仍为 3 席 + 1 主持；用户消息 1 条、纪要 1 份。
- 完成后重复提交 → 拒绝且零新增写入；随后 `retry=true`（新动作）正常只重跑失败席位。

1. 标题行按钮逐字竖排 → `flex-wrap` + `whitespace-nowrap`。
