# UI 参考、复用边界与设计任务

研究日期：2026-11-09 · 状态：候选，未安装，未选定最终视觉稿

用户明确希望借鉴 GitHub 上成熟项目和模板。以下基于官方仓库与文档核查，适配判断来自 Mentora 当前源码；本轮没有完成候选项目的交互实测，也没有看到本地网站实际渲染效果。

## 1. 候选与建议

| 候选 | 已核实的信息 | 建议借鉴/复用部分 | Mentora 的适配工作 |
|---|---|---|---|

| [assistant-ui](https://github.com/assistant-ui/assistant-ui) / [示例](https://www.assistant-ui.com/examples) | TypeScript/React 聊天组件库，MIT；可组合原语，托管云为可选项 | 对话滚动、输入器、消息操作、会话与工具结果呈现的主要参考候选 | 现有 NDJSON、Runner、确认卡和本地会话需适配；不能为采用 UI 默认迁移业务状态或购买云服务 |

| [LobeHub](https://github.com/lobehub/lobehub) | 仓库当前 [LICENSE](https://github.com/lobehub/lobehub/blob/main/LICENSE) 有附加条件，衍生作品开发与分发涉及商业许可要求 | 仅列为完整智能体工作空间的研究候选，后续再实看导航和工作区组织 | 不作为本轮直接复制代码的默认底座；先明确具体版本与使用方式 |

以上许可证结论仅对应所链接仓库本次读取内容；实际采用时固定版本/提交和具体文件范围，保留要求的声明。模板站的付费版、图片、字体和品牌素材不自动继承基础开源仓库的许可。

## 2. 推荐决策

**建议先用 shadcn/ui Blocks 做统一外壳原型，再在 assistant-ui 和 prompt-kit 两条路线中选一条。** 第一条适合把会话体验作为长期组件能力维护；第二条适合先保留当前 Runner/Store，仅替换表现层。当前尚未做适配试验，不能断言哪条成本最低。

选型试验只需同一条任务：已有长对话 → 用户要求改学习阶段 → 显示新旧方案 → 修改草稿 → 应用 → 查看结果。检验多行输入、流式输出、停止、确认卡、历史滚动、中文长文和窄屏。对比实际效果与适配成本，再选定，不先改完整网站。

评分建议：任务可用性 30%、中文内容可读性 25%、现有状态适配成本 20%、组件与状态完整度 15%、维护和许可证清晰度 10%。每项 1–5 分，附截图或可运行证据；本轮没有为候选打虚构分数。

## 3. 具体借鉴映射

| Mentora 页面 | 可借鉴的骨架 | 仍须按产品设计的内容 |
|---|---|---|
| 全站导航 | shadcn sidebar-07 的折叠导航、账户菜单；登录 Blocks 的表单结构 | 模块命名、选中态、未完成任务提示、旧路由兼容 |
| 首页智能体 | assistant-ui 的对话原语/示例，或 prompt-kit 的消息和输入器 | 当前对象、方案差异、授权语义、保存结果、恢复入口 |
| 学习项目 | 同一组件系统的侧栏、列表、详情和 Sheet/Dialog | 阶段/日层级，当前学习、历史进度、修改计划流程 |
| 阅读 | 折叠侧栏、可调整详情区、长文排版和上下文面板 | 当前材料、认知地图、路线、问题讨论、验收与沉淀的先后关系 |
| 人生伙伴/圆桌 | 同一会话组件和人物列表 | 单人/多人区别、席位状态、分歧与主持总结、部分失败 |
| 笔记与回顾 | 列表/内容/属性布局，搜索与过滤组件 | 双链、来源、复习、掌握证据和真实进展 |

这些是设计建议，不能当作已经确认候选具有 Mentora 的业务功能。后台模板中的统计图表和数据表不应原样占据个人学习首页。

## 4. 首轮必须交付的原型画面

先做同一套真实示例内容下的以下画面，覆盖桌面和移动浏览器。2026-11-10 已补充[双流程演示原型](D:/zcode/agent/mentora/docs/web-polish-2026-11-09/prototype.html)，覆盖扩容教学、预设追问、小题反馈、计划草稿、应用和恢复。其余画面及真实失败状态仍待制作；现有原型未完成视觉实测。

1. 首页空会话与进行中的长对话：简答、深讲、代码、引用和图片。
2. 学习项目页：当前阶段/日、继续学习、调整计划和历史入口。
3. 智能体修改方案：新旧差异、影响范围、局部调整、应用/取消。
4. 执行结果：全部完成、部分失败、同步中、冲突和恢复。
5. 阅读工作区：有材料的当前节点、路线折叠、讨论与保存沉淀。
6. 人生伙伴：人物选择、单人讨论、圆桌发言与总结。
7. 笔记页：搜索定位、来源、内容编辑和复习状态。
8. 全局状态：未登录、无数据、额度不足、离线/失败、设置与账户菜单。

## 5. 设计规范草案

- 一套字号、间距、圆角、边框、阴影、颜色和图标规范；不把多套模板的视觉特征直接拼接。
- 主内容优先。学习和阅读的路线、状态和历史可按需展开；长文章的行宽和字号优先于装饰卡片数量。
- 同一语义使用同一组件：方案卡、执行状态、保存状态、来源、错误恢复、空状态在各模块一致。
- 输入区域支持多行和组合输入；按钮不要仅靠悬停才能发现。窄屏抽屉有明确打开和关闭方式。
- 只在真实状态变化时展示进度。展示“正在准备方案”“已更新第二阶段”，不生成伪造的内部思考剧本或虚假完成百分比。
- 视觉验收使用当前真实长内容、失败状态与旧数据，不能只看空白首页或短占位文案。
