第 02 阶段 · 指针与动态内存

扩容时，数据到底去了哪里？

把结构体、指针和数组放进同一张图，再走一遍扩容过程。

“我还是没明白：为什么要用 tmp？扩容以后，size 为什么不变？”

先把三个东西分开

一个顺序表需要记住：数据在哪里、已经用了几个位置，以及总共有多少位置。这三件事分别由 a、size 和 capacity 表示。

结构体 SL → 连续存储的数组（地址 A、B 仅为示意）
a → Asize = 4capacity = 4
地址 A · 原来的数组

a 保存地址；真正的四个整数放在它指向的空间里。size = 4 表示四个位置有有效数据；capacity = 4 表示当前最多能放四个元素。

扩容成功后可以多放几个元素，但还没有插入新元素。所以容量可以变成 8，size 仍然是 4。

为什么需要 tmp？

我们想把容量从 4 扩到 8。realloc 可能成功，也可能失败：成功时返回调整后的地址；本例请求非零空间，失败时返回空指针，原来的内存仍保留。

因此，先让临时变量 tmp 接住结果。确认成功以后，再更新顺序表中的地址和容量。

int grow(SL *ps, int newCapacity)
{
    SLDataType *tmp = realloc(
        ps->a, newCapacity * sizeof *ps->a);

    if (tmp == NULL)
        return 0;  // 未扩容，原数据和容量保留

    ps->a = tmp;
    ps->capacity = newCapacity;
    return 1;
}
  1. ps->a 找到原来的数组。这里的 ps 指向顺序表结构体，ps->a 是该结构体里保存的数组地址。
  2. newCapacity * sizeof *ps->a 把需要的元素数量换算成字节数。本例假设每个元素占 4 字节，8 个元素需要 32 字节。
  3. tmp == NULL 时返回失败。调用者应停止本次插入，不能继续写入原本已满的数组。
  4. 成功后，ps->a = tmp 接受新的地址；capacity 更新为 8。原地扩容也可能成功，地址并不一定变化。
这段教学代码有哪些前提？

这里假设 ps 指向已经正确初始化的顺序表，newCapacity 为合法正数、足够容纳有效数据，且所需字节数不会溢出。完整实现还需验证这些条件。扩容成功后应使用返回的指针；若旧空间被搬迁，不能继续通过旧指针访问。

换个角度理解失败情况

最容易混淆的是：申请失败，不意味着原来的数组消失了。真正的问题是把唯一保存原地址的变量覆盖掉。

预设追问示例

假设 a 原来保存地址 A。直接执行 a = realloc(...)，一旦返回 NULL，赋值会让 a 变为 NULL。原内存还在，但如果没有其他地方保存地址 A，就失去了访问它的入口。

用 tmp 接收时，失败只会让 tmp 变成 NULL；a 仍保存地址 A。于是你还能保留原数据，并告诉调用者这次没有扩容。

保护的是失败时还能找到原数据的能力。
