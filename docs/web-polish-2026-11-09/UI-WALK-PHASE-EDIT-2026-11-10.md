## 2. 证据强度说明（重要）

**这批证据覆盖的是：** 真实浏览器渲染、真实 localStorage 持久化、真实 `computePhaseEdit` / `applyPhaseEdit` / `executeTool` / `executeAction` / `restorePlanVersion` 代码路径。

**这批证据不覆盖：** 通过**自然语言对话**让模型调用 `edit_phase` 工具、审批卡在对话流中的真实出现与点击、跨真实标签页的 storage 事件竞争。原因：自然语言链路需真实模型（每次 30s–2.5min）且结果不确定，不适合作为数据正确性验收。

因此：**数据正确性与 UI 呈现已验收；「对话→审批卡」的端到端链路仍需单独人工走查。** 不得用本报告宣称后者已通过。

## 3. 走查中发现并修复的缺口

| # | 缺口 | 修复 |
|---|---|---|
| 1 | 审批卡预览只报「保留 N 天、新增 N 天」，未列出具体天标题（违反 PRD §5.3「至少显示原内容与新内容」） | `DayDiff` 增 `oldTitles/newTitles`；预览改为逐行列出「原：… / 新：… / 保留：… / 新增：… / 移出：…」；阶段顺序变化也改用阶段名而非 id |
| 2 | 冲突拒绝后只有一句「请重新查看差异」，没有明确的重新生成入口 | 冲突文案改为「检测到冲突…请重新生成方案：再描述一次你想怎么改，我会基于最新内容重新展示差异，确认后再应用」；走查验证重新生成一次可成功应用 |
