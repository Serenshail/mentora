# Mentora 网站体验与全站智能体 PRD

版本：0.2 · 更新日期：2026-11-10 · 状态：评审稿

产品负责人：项目主人。文档整理：Codex。核心方向来自本次会话，尚未选择最终视觉方案；已收到并完整阅读四段 C 语言教学样例，用户认可其细致、透彻的讲解，并同意先打磨教学与计划修改两条体验。本文的建议值与交互方案不能当作用户已逐项确认。

## 1. 产品目标

让 Mentora 成为一个能理解用户、帮助学习与思考，并直接完成网站内业务操作的个人工作空间。用户可以从对话开始，也可以进入学习、阅读或人生伙伴工作区；两种路径使用同一份业务数据，能够继续同一项工作。

本次保留核心功能，主要改善三项结果：

1. **回答值得用：** 回答贴合问题与背景，解释清楚，有依据，有判断；需要简短时简短，需要深入时充分展开。
2. **事情做得成：** 智能体能执行用户权限内的网站业务动作，尤其是协商并修改学习项目及阶段；不能停留在“建议你去某页点击”。
3. **网站用得顺：** 导航、页面层次、阅读排版、任务状态和结果呈现一致，用户知道自己在哪、下一步是什么、修改了什么。

## 2. 目标用户与任务

首批以项目主人及同类个人学习者为验证对象。这是当前假设，不是已经完成用户研究的人群结论。

| 场景 | 用户想完成的事 | 结束时应该看到什么 |
|---|---|---|
| 随时提问 | 看懂问题、材料或概念，获得可用判断 | 合适深度的回答，必要证据与可选下一步 |
| 调整学习 | 现实时间或目标改变，原计划需要调整 | 指定项目和阶段被正确修改，原学习成果可追溯 |
| 带着问题读书 | 理解观点、讨论问题、调整阅读路线 | 原文/导读边界清楚，路线和笔记更新 |
| 讨论人生问题 | 从不同观点审视一个实际选择 | 可区分的观点、分歧、条件化建议和行动 |
| 回顾与积累 | 找回笔记、理解进步、继续上次工作 | 真实记录、可恢复入口、明确当前状态 |

## 3. 范围与交付边界

**本轮文档范围：** 网站现状分析、PRD、能力矩阵、UI 参考、验收用例、交付流程。

**网站打磨完整范围：** 首页智能体、导航和通用组件、学习教练、阅读、人生伙伴与圆桌、笔记和学习记录；账户设置、登录、空白/错误/额度状态等辅助页面同步适配。最终以能力矩阵覆盖现有用户业务动作。

**暂缓：** 微信小程序实现、Obsidian 插件新功能、多人团队协作、重做商业模式、扩展无关领域。网站需要保持数据兼容，后续小程序复用业务约定与设计语言；它仍需针对微信交互、存储和布局做适配，不预设复制网页即可交付。

**权限边界：** “全站操作”指当前用户权限内的个人业务操作。涉及付款、密码、密钥、整账户清空等，智能体可解释并打开对应受控流程，由用户完成必要身份验证和决定；不能因为自然语言入口而扩大权限。管理后台是否纳入是独立待定项，不混进个人助手的承诺。

**优先级：** P0 是第一批完整流程必需项；P1 是网站整体完成前必须覆盖的其余核心体验；P2 是非阻塞增强。P1 不等于可永久不做。所有现有功能都必须在页面审计清单中有去向。

## 4. 建议的信息架构

```text
Mentora
├─ 智能体：当前会话 / 历史会话 / 本次任务与产物
├─ 学习教练：目标列表 → 项目 → 阶段 → 学习日与验收
├─ 阅读：书架 → 阅读工作区 → 路线 / 材料与讨论 / 沉淀
├─ 人生伙伴：人物对话 / 圆桌讨论 → 会话与行动
├─ 笔记：检索 / 内容 / 关联 / 复习
├─ 学习记录：进展 / 掌握证据 / 回顾
└─ 账户与设置：个人偏好 / 模型 / 同步 / 会员与帮助
```

这是建议导航方案。保留“学习人生”的内容，建议在导航中改为更易理解的“学习记录”；最终命名通过原型确认。圆桌是人生伙伴中的讨论形式，不另造一套互不关联的会话系统。

首页智能体负责通用对话与跨模块操作；专业工作区保留最适合该任务的布局。各页的“问智能体”应携带当前对象和选中内容，并清楚显示这些上下文。帮助入口只处理产品使用说明，不能与业务智能体争夺同一任务。

旧链接保留兼容；页签、对象选中、浏览器后退/前进/刷新应一致。菜单名称、页面标题和智能体描述使用同一套名称。

## 5. 关键流程：讨论后修改学习阶段

示例为产品设计样例，不是用户已经提供的真实失败案例：

> “我最近每周只能学 3 小时，把 Python 项目后面两个阶段调整一下。保留已完成的内容，多一点能用在工作里的练习。”

1. 读取该用户现有目标、阶段、当前进度及与本次请求相关的已知约束。当前页面已明确项目时直接使用，不再问“哪个项目”。多个 Python 项目且无足够上下文时，展示候选供选择。
2. 汇总已知事实：“每周 3 小时；调整第二、三阶段；保留已完成记录；增加工作场景练习。”缺少会实质影响方案的工作场景时，提出聚焦问题；用户明确给出场景则直接继续。
3. 生成可讨论草稿。至少显示：目标项目、受影响阶段、原内容与新内容、顺序或周期变化、保留内容、对当前进度的影响。此时业务数据尚未被替换。
4. 用户可说“第三阶段再短一点”“只修改第二阶段”“先不要改”。修改草稿只更新受影响部分；拒绝或取消不产生业务写入。
5. 当用户接受具体方案后应用。如果用户最初已明确指定确定性小改动，例如“将第三阶段标题改成 X”，可按该指令直接执行并提供撤销，不重复询问同一授权。结构重排、删除与覆盖仍要让用户看到具体影响并决定。
6. 写入前检查对象仍存在，且版本未发生冲突；有冲突则读取最新数据重新展示差异，不能静默覆盖。
7. 成功后显示准确结果和“查看计划／查看改动／恢复上一版本”。原学习页面同步更新。只保存到本机时标明“本机已保存，正在同步”；同步失败不能宣称云端已保存。
8. 一部分成功时，分别列明已完成和未完成部分。取消只能阻止未提交动作，不能把已提交修改伪装成从未发生。

**验收核心：** 用户不用重新讲已知背景、不用自己寻找编辑入口；只有指定对象发生授权变更；已完成学习记录、验收证据和笔记关联保持可追溯；刷新后仍能验证结果。

## 6. 回答质量要求

| ID | 优先级 | 要求与验收 |
|---|---|---|
| AQ-01 | P0 | 按意图和用户要求决定深度。单点问题直接回答；讲解给必要的原因、例子和易错点；详细分析按材料组织，不强制每次九段式。验收：同一内容在“只要结论”“详细讲解”下明显不同，均满足要求；没有用户要求时不自动建学习目标。 |
| AQ-02 | P0 | 延续用户背景和对象上下文。切换到学习、阅读或圆桌后，带上已知目标、约束和相关内容；长对话重要约束可找回。验收：跨工作区与超过当前九条上下文窗口的测试均保留指定事实，不串到另一会话。 |
| AQ-03 | P0 | 答案、练习和反馈针对当前材料。检验题必须检验刚讲的知识，不能误用别的活跃项目；有明确学习表现才能声称掌握。验收：题目与指定知识点一一对应，答案未提交时不标“已掌握”。 |
| AQ-04 | P0 | 事实和执行结果有依据。书目已核实不等于拿到了全文；原文、AI 导读、用户笔记和外部资料可区分；工具失败不报成功。验收：没有原文时不编页码或逐字引文；引用可打开或清楚标记不可取得。 |
| AQ-05 | P0 | 允许用户纠正和调整。用户指出错误时核对依据并修正；复杂规划逐步沟通，避免重复问已知问题，也不设机械的“一次提问后无论如何必须执行”。验收：新增约束能改变方案，用户说“只是讨论”时无写入。 |

“回答有思路”在本 PRD 中表现为：必要的解释、证据、判断条件、执行计划与结果。页面展示面向用户的工作摘要和真实动作状态，不以展示模型内部完整推理作为质量或验收目标。

2026-11-10 已登记 REF-01～REF-04，详见[教学参考与原型说明](D:/zcode/agent/mentora/docs/web-polish-2026-11-09/TEACHING-REFERENCE.md)。样例用于定义教学行为，已发现的事实错误不进入参考答案。明确要求详细讲解时，应完整展示关键原因与中间变化；用户仍不理解时，应验证卡点并换一种讲法。

后续理想回答样例登记格式：样例编号、原问题、相关上下文、当前回答、用户期望回答、喜欢/不喜欢的具体点、不可省略信息、允许的其他表达。暂不写固定人设或模仿某个产品的全部话术。

## 7. 智能体操作要求

| ID | 优先级 | 要求与验收 |
|---|---|---|
| AG-01 | P0 | 精确定位。读写动作绑定确定的项目、阶段、书、章节、笔记或会话；标题歧义要消歧。验收：两个同名或近似名称对象下只修改被指定对象。 |
| AG-02 | P0 | 将讨论、草稿、执行区分开。草稿可调整；明确授权的简单动作直接执行；结构性改动提供具体差异再决定。验收：接受/修改/取消均有独立状态，同一方案不重复请求确认。 |
| AG-03 | P0 | 精确编辑学习目标与阶段。支持调整时间约束、阶段目标与标题、顺序、增删阶段、阶段内日目录、任务/练习和资源约束；支持只改选定部分。验收：按能力矩阵 L01–L06 的场景逐项完成；不能用“整段随机重生成”替代局部编辑。 |
| AG-04 | P0 | 保留成果与恢复。修改前保留可追溯版本；已完成日、验收记录、笔记关联不因重排消失。移出当前路线的旧内容标为历史，不计入新路线当前进度。恢复只回退该次计划变更，不能顺带覆盖之后新增笔记和成绩。 |
| AG-05 | P1 | 接通阅读与笔记业务动作。能够读取详细对象、修改阅读目标/路线/顺序/状态、沉淀和编辑笔记、检索与关联。验收：自然语言和页面操作产生一致的业务结果；读完、跳过和掌握分别记录。 |
| AG-06 | P1 | 接通人生伙伴与圆桌动作。读取/继续指定会话、选择人物、启动讨论、整理结论和保存行动，支持已有的人物管理流程。验收：创建会话后能继续讨论，原问题与约束完整传入，失败席位可单独重试。 |
| AG-07 | P0 | 可取消、可追踪、可处理部分失败。停止后不再启动新动作；已提交结果仍列明；重试不得重复创建或写入。验收：网络重试、重复点击、切会话及中途退出下无重复对象或串写。 |
| AG-08 | P0 | 成功声明对应真实状态。结果包含变更对象、变更摘要、目标页面与保存状态；读取当前状态复核关键写入。验收：用户从结果打开页面和刷新后看到一致内容；失败与未同步不冒充成功。 |
| AG-09 | P1 | 覆盖全站个人业务操作。以能力矩阵逐项映射页面入口和智能体动作，未实现必须如实显示；只提供入口跳转不计为“可操作”。验收：上线范围内所有应直接执行的动作覆盖率 100%；受控账户流程单列，不混入分子。 |

## 9. 各核心页面的设计要求

### LEARN-01 · P0 · 学习教练

项目页首先说明“目标是什么、当前阶段、下一步要做什么”。阶段目录可折叠，当前学习内容为主；历史、完整计划和统计为次。阶段操作可从页面直接开始，也能交给智能体；两条路径使用相同修改规则。修改方案应明确变化、预计负担和保留内容。

验收：首次打开进行中项目，用户能找到继续学习与调整计划；重排后当前进度只统计当前路线中的有效节点；历史成绩仍可查；已掌握与用户选择跳过不混为一谈。

### READ-01 · P1 · 阅读

书架重点是继续读什么、为什么读；阅读工作区以当前材料和问题为主。路线侧栏负责导航，右侧辅助区展示当前目标与沉淀，空间不足时折叠。认知地图可展开，不在每次进入时挤占主要阅读区。验收、沉淀、迁移作为有上下文的动作渐进出现。

验收：用户无需离开当前材料即可提问和保存笔记；能修改阅读目标和路线；AI 导读与用户提供材料的来源标记明确；不因切换章节丢掉草稿或串用上一章上下文。

### LIFE-01 · P1 · 人生伙伴与圆桌

人物选择、进行中的对话和结论分别组织。单人对话突出该人物的分析视角；圆桌可清楚识别发言者、各自进度和核心分歧，主持总结区给出共识、分歧、判断条件和可选行动。默认让用户读清楚内容，不强制同时展示多列长篇输出。

验收：部分人物失败时保留其他发言并可单独重试；主持不把未取得的观点当已发言；将讨论转为学习目标或笔记时携带必要背景；人物观点是模拟分析，不编造现实人物对此次问题的真实发言。

### NOTE-01 · P1 · 笔记与学习记录

笔记统一承接学习、阅读和圆桌成果，用户能从来源回到内容，也能找到关联与复习。学习记录聚合真实进度和证据，不把生成目录、跳过任务或普通聊天等同于能力提升。

验收：来源可追溯；搜索命中可打开；用户能保留原文、编辑、归类、关联与选择是否复习；修改和恢复计划不覆盖笔记新编辑。

### AUX-01 · P1 · 账户与基础页面

登录、设置、会员/额度、帮助及产品介绍沿用同一视觉系统。给出当前模式和可用能力；演示模式不能冒充真实模型质量；用户退出登录或切换账户时不显示其他账户内容。管理员页面保留现有职责，视觉改造深度另行评估。

## 10. 数据与质量要求

| ID | 优先级 | 要求 |
|---|---|---|
| DATA-01 | P0 | 当前数据可迁移，修改前后有版本与关联；计划历史、有效节点、成绩和掌握证据口径统一；不删除既有成果来解决重排问题。 |
| DATA-02 | P0 | 同步与冲突可见，跨页/刷新后结果一致；旧客户端或不完整快照不能静默清空新字段。本轮不开发小程序，但要验证共享数据契约不会造成 Web 丢失。 |
| QUAL-01 | P0 | 有固定回答基线、真实写入验证和失败路径用例，记录模型、提示词、应用版本、数据初态、耗时与成本；不得合并多次最好成绩充当首次成功率。 |
| PERF-01 | P1 | 先测再定优化点。记录首个有用内容时间、总耗时、操作反馈、页面可用时间与每次成功任务成本；流式占位动画不计入首个有用内容。大笔记库与长会话要单独测试。 |

## 11. 建议验收指标

以下是**提案目标，当前均未测量**。在基线阶段确认数据规模与运行环境，再冻结正式发布阈值；不能因候选版未过而事后放宽同一批标准。

| 维度 | 测量口径 | 提案目标 |
|---|---|---|
| 回答质量 | 固定至少 30 个问题，盲评旧版与候选版；记录胜/平/负及评分理由 | 候选版胜出 ≥60%，胜或平 ≥90%；关键事实错误单列阻塞 |
| 任务执行 | 至少 30 个明确应执行的常规任务，每项独立三次，统计每次第一次执行结果 | 首次正确完成率 ≥95%；不能靠人工补点完成 |
| 数据正确 | 同名对象、保留进度、取消、重试、冲突、账户隔离等确定性用例 | 全部通过；错对象、丢记录、未授权修改为发布阻塞 |
| 易用性 | 5 名目标用户各做 5 条核心任务，记录完成率、时间和困难点 | 无口头帮助完成率 ≥90%，关键任务无阻断；小样本只用于发现问题 |
| 界面完整性 | 页面×关键状态×视口检查表 | 所有 P0/P1 页面关键状态完成，无阻断操作或正文遮挡 |
| 交互反馈 | 本机可控操作，记录点击到可见反馈 | 建议 P95 ≤500ms；模型耗时另测，不以动画掩盖 |
| 性能与成本 | 相同设备、网络、数据、模型，分别比较 P50/P95 和成本 | 无未经解释的显著退化；数值预算在基线后冻结 |

主观偏好用用户样例与原型评审确认；可靠性用数据和任务结果确认。不能用平均分掩盖错改学习计划或虚报完成。

## 12. 实施顺序与待定项

第一批：同时打磨两个具体场景——充分讲解、针对性追问与检验，以及讨论后精确修改学习阶段。先用用户样例定义教学质量，再以两条交互原型确认内容、层次和操作；随后完成真实模型基线与真实业务接入验收。独立演示原型不代表模型或数据链路已实现。

第二批：接通阅读、笔记、人生伙伴与圆桌的业务动作，完成专业工作区的设计和全站状态适配。

第三批：完成能力矩阵全覆盖与大数据/长会话体验、全站回归和真实用户试用，稳定后再启动小程序适配。

待定：样例标准的最终评测集（首批已收到）；最终视觉方向与命名；管理员动作是否纳入后续；常用模型与成本预算；正式发布指标。当前不阻塞文档产出，但相关项冻结前不声称“回答效果/视觉方案已被用户认可”。
