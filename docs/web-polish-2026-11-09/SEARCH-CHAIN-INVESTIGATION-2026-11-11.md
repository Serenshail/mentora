# 搜索链路排查报告

**日期：** 2026-11-11 ｜ **触发：** in13 加书核查必然失败（[EVAL-01 §4.4](./EVAL-01-CALIBRATION-2026-11-10.md)）
**方法：** 逐层探针（原始 HTML 抓取 + 对照实验），全部证据存 `docs/evidence/search-probe/`
**纪律：** 判定逻辑 `judgeBookEvidence` 一字未动；**未放宽书籍核查**

## 1. 链路结构与各层结论

```
调用方(verifyBook) → /api/search 网关 → [TAVILY → BRAVE → Bing解析 → DDG兜底]
```

| 层 | 结论 | 证据 |
|---|---|---|
| 查询构造 | **垃圾入口①（决定性）**：`book-verify.ts:105` 拼出「书名 作者 书 书籍」**多词查询** | 代码 + 复现 |
| Bing 上游 | **垃圾入口②（根因）**：多词查询触发 Bing 反爬**降级**——只按第一个词返回通用结果（词典页/无关站点）；**单词查询完全正常** | A/B/E/F/G 实验（§3） |
| 解析 | 无问题：垃圾就在 `b_algo` 块里，解析器如实提取 | 原始 HTML（已存档） |
| 缓存 | 链路无缓存层 | 代码 |
| 降级链 | TAVILY/BRAVE 未配 Key；DDG 对本网络超时（数据中心 IP 封锁，与代码注释一致）→ **Bing 是唯一活通道** | env 检查 + 超时实测 |

## 2. 关键实验

### 实验 A/B/D：host / cookie / ensearch 变体 —— 全部同样降级

查询「思考 快与慢 卡尼曼 豆瓣」四种方式返回**完全相同**的降级结果（「思考」的词典解释）：

| 变体 | 结果 |
|---|---|
| cn.bing.com 基线 | 「思考（汉语词语）_百度百科」… |
| www.bing.com 基线 | 同上 |
| cn.bing.com 带 cookie | 同上 |
| www.bing.com ensearch=1 | 同上（标题同、URL 是 bing 跳转链） |

### 实验 E/F/G：单词 vs 多词 —— 决定性差异

| 查询 | 结果 |
|---|---|
| E1 单词「卡尼曼」 | ✅ 百度百科/知乎 正确结果 |
| E2 单词「思考快与慢」 | ✅ **第一条即豆瓣图书条目** `book.douban.com/subject/10785583/` |
| F1 多词「思考 快与慢 卡尼曼」（%20 与 + 均试） | ❌ 降级：只按「思考」返回词典 |
| G1 多词「影响力 罗伯特西奥迪尼 豆瓣」 | ❌ 降级：只按「影响」返回词典 |

**结论：降级与 host、cookie、编码方式无关，与「查询含空格（多词）」强相关。** 降级结果在不同时间还会变化（前一轮是 MSN 游戏/poki 小游戏，后一轮是词典/美容店），符合反爬降级特征。

## 3. in13 失败的完整因果链

1. `verifyBook("影响力", "罗伯特·西奥迪尼")` 构造查询 `影响力 罗伯特·西奥迪尼 书 书籍`（4 词）
2. Bing 降级 → 只按「影响力」返回词典/无关页面
3. `judgeBookEvidence` 在结果中找不到可信书目域的具体条目 → 正确判 `insufficient`
4. `add_book` 按纪律拒绝创建 → in13 交互失败

**核查纪律本身工作正常**——它挡住了「没有真实证据」的创建。问题在查询策略喂给它的是被降级的搜索结果。

## 4. 修复（已实施并验证）

**改动（唯一）：** `src/lib/book-verify.ts` 新增 `buildVerifyQuery(title)`——查询改为**书名单 token**（去书名号/空白合并）；**删除**「作者 书 书籍」后缀拼接。
**不改动：** `judgeBookEvidence` 判定逻辑（作者匹配、可信域白名单、标题前 8 字规则全部保持）——**不是放宽核查，是修正喂给核查的查询**。

**验证（搜索层端到端）：**

| 书 | 修复前 | 修复后 |
|---|---|---|
| 《影响力》（罗伯特·西奥迪尼） | insufficient（垃圾结果） | **verified**：4 条可信命中，豆瓣条目 `subject/35637771`，作者匹配 ✅ |
| 《思考，快与慢》（丹尼尔·卡尼曼） | — | **verified**：豆瓣条目 `subject/10785583` 第一条，作者匹配 ✅ |

**测试：** 新增 `buildVerifyQuery` 3 项单测（单 token、去书名号/空白、不再拼后缀）；既有 book-verify/search-bing 测试 26 项全过。

**验证边界：** 浏览器级完整 `add_book` 未能跑通——D1 数据库通道持续 503，登录不可用，无法建测试会话。搜索层验证已闭环（verifyBook 的输入输出就是 add_book 消费的全部接口），待 D1 恢复后补浏览器级确认。

## 5. 遗留与建议

1. **web_search 工具同样受多词降级影响**：智能体任何多词联网搜索都会拿到降级结果。这是比 in13 更大的影响面。根治靠配置 TAVILY/BRAVE Key（部署侧动作，一条 env）；代码侧缓解（如多词拆分重试）留待后续评估——避免在冻结期改共享网关。
2. **Bing 降级是猫鼠游戏**：单词查询当前可靠，不保证长期。生产部署建议配置付费搜索 Key。
3. **rate-limit**：搜索 20 次/天/用户，add_book 每次消耗 1 次搜索；修复后无重试不增加消耗。
4. 探针脚本保留在 `scripts/probe-search-chain.mjs` / `probe-search-ab.mjs` / `probe-search-e2g.mjs`，供复核复现。
