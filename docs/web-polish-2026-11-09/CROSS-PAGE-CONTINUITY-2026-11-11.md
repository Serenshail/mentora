## 2. S1/S2/S4 未完成的原因（如实）

**不是产品缺陷，是自动化定位失败。** 具体障碍：
1. 笔记工作区的编辑需要两步：点「编辑」→ 默认 live 模式无 textarea → 再点「源码」切 raw。已实现该逻辑（`enterRawEdit`），但…
2. 笔记在多层文件夹树里（样例 domain `验收/笔记`），文件夹行本身不是按钮，展开开关是**行内第一个 button**，且搜索后树会重建。
3. 每次尝试都因「先展开再搜索」的顺序问题错过目标，耗时在 2 分钟以上。

**已放弃继续调选择器**（避免陷入循环），改用：
- S5/S6 已用真实界面验证了**跨页连续性与来源提示**（本轮最关键的命题）；
- 编辑落库链路用**源码 + store 契约**验证（8 项全过）。

## 3. 对本轮核心问题的回答

> 用户正常使用本来就会跨页、刷新并继续操作——这到底通不通？

**S5 直接回答：通。** 同一对象（学习阶段）在「首页改 → 专业页看 → 回首页再改 → 专业页看 → 刷新」全链路一致，第二次修改生效且刷新后保持。**跨页连续性在数据层面成立**（依赖云端同步 + 水合）。

> 笔记正文的持久化呢？

**未直接验证到。** E3 曾观察到「刷新后 body 为空」，但本轮 S5 证明结构化字段（阶段标题）持久化正常。两者差异可能在于：笔记正文走 350ms 防抖 + 独立 writer 路径。**该差异未定位，保留为待查项。**
