## 2. 新的详细教学标准

1. 明确要求详细讲解时，允许充分展开，不能为了简短删除关键因果和中间步骤。
2. 先交代任务与预期结果，再展开结构和实现；新概念在需要时解释。
3. 核心表达式能带入具体数据；状态变化能逐步复核，代码与图示使用同一组数据。
4. 同时说明“如何工作”和“为什么需要”；必要时用反例展示省略某一步的后果。
5. 解释到足以支持用户独立操作，再给有针对性的检验；一题正确只说明这一题的表现，不代表整个知识点已掌握。
6. 用户仍不懂时，提出可验证的卡点假设，改变例子或表达方式；不要未经确认就断言用户缺少哪个知识。
7. 依据已知背景减少重复，但不把用户“看过”当成“掌握”；学习表现与偏好分开记录。
8. 阅读、人生决策和圆桌沿用充分解释与有据判断，不机械套用编程讲解结构。

这补充 AQ-01～AQ-05，不新增重复需求编号。最终模型验收需要同一问题和上下文下的真实输出；本次手写原型不计入回答质量指标。

## 3. 可点击原型

[打开双流程原型](D:/zcode/agent/mentora/docs/web-polish-2026-11-09/prototype.html)

原型为独立 HTML，无外部依赖、联网请求或真实账户数据。讲解、示例回复和学习记录均为设计样例；操作只改变当前页面内存中的演示状态，刷新重置。未运行本地网站，也未绕过此前的浏览器来源限制。

**流程 A：理解扩容。** 阅读目标 → 结构体与数组示意 → 模拟扩容成功/失败 → 逐步代码解释 → 针对临时指针的预设追问 → 小题与反馈。此版本的交互重点是完整教学过程，不实现任意自由问答。

**流程 B：调整学习。** 从教学页进入指定项目 → 查看用户请求与已知约束 → 选择补基础还是穿插练习 → 形成具体草稿 → 调整课次数量 → 应用到示例计划 → 查看/恢复。取消不改计划；应用不会改示例已完成课数和笔记数；恢复只恢复此次示例计划。

示例场景：C 语言数据结构项目；已完成数组阶段；当前学习指针与动态内存；后续为链表。用户要求先巩固指针再进入链表，每周三小时。以上初态为设计假设，不是读取到的用户真实学习记录。

## 4. 评审重点

| 流程 | 希望确认的体验 | 不能从原型推导的结论 |
|---|---|---|
| 教学 | 解释是否有遗漏；状态演示是否帮助理解；长内容是否好读；追问是否有针对性 | 模型已经能稳定生成这种内容；用户已经掌握知识 |
| 调整计划 | 对象和影响是否清楚；用户能否修改方案；结果与恢复是否易懂 | 真实数据库、同步、版本冲突、跨设备恢复已实现 |
| 整体 | 两个流程是否连续；主内容是否突出；布局是否符合用户喜好 | 其他核心模块已经完成设计；模板选型已经结束 |
