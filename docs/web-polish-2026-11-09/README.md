## 已确认的方向

1. 保留学习教练、阅读、圆桌会议和人生伙伴的产品主干，改善回答质量、操作能力、整体排版与交互。
2. 首页智能体应理解用户正在做的事，通过对话完成网站内的业务操作；用户明确举例：讨论后修改某个学习项目的不同阶段。
3. UI 可以采用成熟开源组件和模板；先统一设计方案，再按真实内容验证。
4. 工作顺序为现状分析 → PRD → 原型与设计规范 → 技术方案与任务拆解 → 分批实现 → 验收 → 发布。已完成分析与 PRD 初稿，进入两条核心流程的原型讨论。

2026-11-10 决定先共同打磨“详细教学、追问与检验”和“讨论后修改计划”两条体验。操作流程为：**用户提出学习调整 → 定位项目和阶段 → 理解约束 → 展示具体修改方案 → 应用修改 → 原页面立即看到结果 → 能追溯与恢复**。这条流程同时检验回答、智能体执行和 UI，适合作为第一批实现；后续扩展到阅读和人生伙伴，最终覆盖能力清单，而非把首批范围当成全部产品。
