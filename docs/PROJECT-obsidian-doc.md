## 0. 这个项目是什么（30 秒版本）

Mentora 把 Obsidian 里沉淀的学习方法论（6 段教学模板、双验收、间隔重复 1/3/7/15、知识点穷尽原则）产品化成一个 Web 应用，并合并了两个旧项目设想（智能体读书、人生伙伴）。四个功能：

1. **学习教练**——你说想学什么，教练先真正了解你（目的、基础、时段习惯、学习风格、放弃史、性格倾向、约束），然后自己推导行业要求，排出「阶段→天」两级计划；每天一课按你的 6 段教学模板生成，逐条验收，**通过才解锁下一阶段**，学不会可以硬跳过（需输入「跳过」二次确认并留痕）。
2. **第二大脑**——Obsidian 式双链笔记库：每条知识是独立笔记，正文支持 `[[标题]]` 双链、出链/反向链接面板、力导向关系图谱（可拖拽）、AI 建联（在整库里找有思想联系的笔记并说明理由）；知识点按 1/3/7/15 天间隔重复提醒，回忆式复习。
3. **读书伙伴**——深度解剖一本书：先写书籍档案（定位/作者与立场/思想谱系/争议），按论证逻辑（而非目录）拆解单元，每个单元带核心论点、带读问题、其他思想家交叉视角；陪读对话完全随机应变，洞见一键提炼成笔记入第二大脑。
4. **人生伙伴**——反迎合内核（8 条判断纪律）+ 12 位深度蒸馏的名人 persona + 圆桌研讨会（全员并行独立发言 + 主持人纪要）+ **自定义智能体锻造**（输入一个名字，AI 蒸馏到「本人降临」级别）。

**产品哲学**（决定一切 UI 与文案决策）：乔布斯式做减法 + 纳瓦尔式的具体；第一句话就是判断；文案像人话不像产品说明书；验收不放水；数据归用户。

## 1. 项目缘起与需求演进史（完整决策日志）

这个项目不是一次设计出来的，是**四轮真实反馈各砍一刀**迭代出来的。完整记录如下，这是本项目最值钱的部分。

### v1（2026-09-12 上午）——从方法论到产品

**输入**：Obsidian `Agent学习项目.md` 里的协作方式（AI 发任务模板：目标+精炼讲解+验收线+练习+迷你项目；用户写代码→AI 逐条验收；通过后进入下一知识点并排入间隔重复队列 1/3/7/15 天）+ 6 段教学模板（官方链接→知识点穷尽→完整可运行代码→逐行讲解→变体写法→验收标准）。

**当轮决策**：

### v3（2026-09-12 晚）——对抗 AI 味的三场战争

**用户反馈原话要点**：「读书伙伴太差了，按我之前的方向重做」「蒸馏不够，要仿佛本人降临」「学习过程中要能直接添加笔记」「引导对话太啰嗦，一直追问却不开始行动」「不要死板的截止日期——任务量大时间少，给了日期也达不到」「有些东西你应该自己去搜索思考，比如我目的是应聘，你应该知道学到什么程度能应聘，不能全问我」「计划一直生成出错，肯定是你的问题」

**当轮决策（每一刀都砍在要害上）**：
- **信息 A/B 分类纪律**（引导哲学的重写）：A 类=AI 自己推导绝不问用户（行业标准、学到什么程度、路径顺序）；B 类=只有用户知道的必须问全（目的场景/基础/时段/风格/放弃史/约束/性格/材料偏好）。实测 7 轮深挖，画像五维齐全
- **杀死截止日期**：目标卡删除 deadline 字段，计划用「Day N」相对编号。理由（用户原话的逻辑）：学习量由任务决定，投入多少走多快，绝不承诺做不到的日期
- **计划生成 bug 根治**：原计划内嵌完整代码例子→输出过万 token→Vercel 60s 超时/解析失败。瘦身为「计划只存例子 title+description，代码在授课时生成」→ **60s 超时降到 13 秒**
- **6 段教学模板成为每日文档骨架**（从 Obsidian Day2b 文档逆向提取），验收改回「操作+默写双轨」
- 读书伙伴 v3：书籍档案（定位/作者与立场/思想谱系/争议）+ 每单元 coreIdea/交叉视角/capture 建议拆解方式自选（论证型按论点群/叙事型按问题弧线/工具型按方法箱）
- 自定义智能体 v4：对标 GitHub 顶级人物提示词（结构分层+语言指纹+样例对话 few-shot），1500-3000 字，规避「金句堆砌」（quotation collage）
- 圆桌改全员制：与会者可选（默认全选），每人并行独立发言，主持人综合出纪要（共识/真分歧/被遗漏的视角/下一步）
- 学习页新增随手记 + 即时答疑（AskCoach，按天持久化）

## 2. 学习教练（最复杂模块，详解）

### 2.1 引导流（SOCRATIC_INTAKE v5）

**信息 A/B 分类纪律**是整个引导的灵魂：

| 类别 | 归属 | 例子 | 处理方式 |
|---|---|---|---|
| A 类 | AI 自己推导，**绝不问用户** | 行业标准、要学到什么程度、路径顺序 | 用户说"应聘AI岗"，直接按岗位 JD 推导 |
| B 类 | 只有用户知道，**必须问全** | 目的场景、基础、时段习惯、学习风格、放弃史、约束、性格、材料语言偏好 | 一次一个问题，6-9 轮深挖 |

- B 类八项：目的与场景 / 现有基础 / 时间现实（每周几小时+时段+稳定性）/ 学习风格（视频/文字/动手）/ 过往经历（学过什么、为何放弃）/ 约束（工作家庭设备网络）/ 性格倾向（自驱 vs 外部节奏；死磕 vs 绕行）/ 材料偏好（中文 vs 英文文档）
- 用户不耐烦（「就这样」「别问了」「你定」）→ 立即出卡，缺项写进 `assumptions` 并明示
- UI 常驻「不想再答了——让教练按现有信息直接生成」按钮
- 产出目标卡：topic / direction / domainKind / motivation / background / weeklyHours / **learnerProfile（五维画像）** / successCriteria（A 类推导）/ assumptions（假设透明）
- **无截止日期字段**（v3 决策）：学习量由任务决定
- 对话全程自动保存进草稿目标，随时离开随时回来（`/learn/new?goal=<id>` 恢复）

### 2.2 计划生成（PLANNER）

- 「阶段→天」两级；2-4 阶段 × 每阶段 2-5 天；总输出压到 1500 tokens 内（**60s 超时→13s** 的关键）
- 每天：title / method（体现领域策略）/ knowledgePoints（3-5 个，穷尽到方法级）/ resources（直接可学资料）/ example（**仅编程领域**，且只有 title+description，代码授课时生成）/ acceptance（2-3 条）
- **资源铁律**：点开就能学的直接资料（官方文档小节/免费视频课/交互教程/开源讲义），**严禁购物清单**——纸质书一律替换为免费在线版；中文优先
- **画像个性化**：时段碎片→任务拆 20-40 分钟小块；视频型→资源偏视频；易拖延→每阶段前两天安排最有成就感的任务
- 领域策略预设（METHOD_PRESETS）：coding（6段模板+变体验收）/ language（输入输出循环）/ humanities（大问题导读+观点交锋）/ exam（考纲倒推）/ career（作品集驱动）/ other（数学走定义定理例题变体，其余刻意练习）

### 2.3 每日文档（DAILY_LESSON v5——分领域模板）

**这是从 Obsidian Day2b 文档逆向提取的教学圣经**。编程版六段：

1. **① 直接可学的资料**——2-4 个点开即学的链接，每个注明"看哪一段"
2. **② 知识点穷尽**——基础→拓展→所有形态，穷尽到方法级（如 list：创建全部形态/append/insert/extend/pop/remove/切片全用法/推导式带条件/sort 与 sorted 区别/常用方法）
3. **③ 完整可运行代码**——80-150 行单文件，分组注释+行尾注释，注明怎么跑、建议实跑
4. **④ 逐行讲解**——覆盖所有非显然行，每组四件事：为什么这样写/不这样写会怎样/对应②哪个点/真实项目何时用
5. **⑤ 还可以这样写**——3-5 条变体+易错对照
6. **⑥ 验收标准**——**操作+默写双轨**，每个问题给"合格回答长什么样"

**非编程领域各自独立六段**（v3.3 修复"用代码教政治学"的荒诞 bug）：
- 人文社科：②概念与论证穷尽（定义/提出者/回应什么问题/论证链）→ **③深读：原文细读或案例全程**（这是代码块的对应物）→ ④论证拆解（证据性质/最强最弱环/你会质疑哪步）→ ⑤学派视角对照 → ⑥默写+200字微型论述。**整篇严禁代码**
- 语言：语料全文+输出示范→用法拆解（母语者怎么选/中文母语者易错）→场景变体（正式/口语/书面）→朗读复述+造句验收
- 考试：考点穷尽（命题方式/设错点）→真题全程→命题陷阱→变体题（不给答案留给验收）→限时+讲题双轨
- 数学：直观引入→严格定义→定理（条件缺一个会怎样）→典型例题每步推导→变体与易错→独立解题+讲定理双轨
- domainKind 分支路由：exam 和 other 会再检测数学关键词（微积分/线性代数/概率…）决定走数学模板还是通识模板

### 2.4 验收门与解锁机制

- 逐条验收：explain（默写：用自己的话讲清，背书式复述不算过）/ apply（变体题）/ oral / essay / build
- 评分官提示词明确「不放水，不吹毛求疵」；overall=全部 pass 才 pass
- **通过→解锁同阶段下一天；阶段最后一天通过→阶段 passed→解锁下一阶段首天；全部完成→goal.status=done**
- 不通过→反馈「卡在哪+最小补救动作」+ 留在原地；**强制跳过**需输入「跳过」二次确认，记录为 skipped，知识点不入第二大脑
- 验收记录按天持久化，历史天数可回看
- 通过的知识点自动流进第二大脑并进入间隔重复队列

### 2.5 学习中的两个伴手功能

- **随手记**：每日任务面板内联输入框，想到就记，Enter 即入第二大脑（domain=学习主题，sourceTitle=「主题·Day·随手记」）
- **即时答疑（AskCoach）**：「看不懂？问教练」——展开即迷你聊天，背后连通用大模型；规则：先答案后解释、给最小例子、主动补"你卡在这里通常是因为…"；对话按天持久化（DayPlan.qa）

## 3. 第二大脑（Obsidian 式双链库，详解）

### 3.1 数据模型（v2）

```ts
interface KnowledgeItem {
  id: string; title: string;        // 标题即 wikilink 目标
  body: string;                     // Markdown 正文，可含 [[标题]]
  domain: string;                   // 所属领域（筛选维度）
  source: "learn" | "read" | "council" | "manual";
  sourceTitle: string;              // 来自哪个目标/哪本书
  masteredAt: string; reviewStage: number; nextReviewAt?: string;
  links: string[];                  // 出链：指向其他笔记 id（有向）
}
```

v1→v2 迁移：persist `migrate` 把旧 `{text}` 自动转成 `{title: text, body: "", links: []}`。

### 3.2 四个视图/能力

1. **笔记库**：搜索（标题+正文）/领域筛选/卡片显示来源、复习到期、复习轮次点阵、出链预览
2. **关系图谱**：自研力导向模拟（斥力 O(n²)+边弹簧+向心力+阻尼），SVG 渲染；节点大小随连接数生长、按领域着色、可拖拽、点击打开笔记、悬停高亮邻居
3. **笔记详情**：WikiMarkdown 渲染（[[标题]] 可点击跳转；未创建的显示虚线占位）+ 出链管理（搜索连接/断开）+ **反向链接**自动计算 + 编辑 + 删除（级联清理指向它的链）
4. **AI 建联**：为当前笔记在整库找有思想联系的笔记（判断标准：同一概念的深化/正反例/前提与推论/跨领域同法/互为因果），**宁缺毋滥 0-3 条**，每条给"为什么相关"，用户点击采纳才建立

### 3.3 间隔重复（沿用学习方法论）

- 通过验收/提炼洞见/手动记录的笔记进入队列，`nextReviewAt = today`（当天可首刷）
- 复习流程：AI 出回忆检验题（逼主动回忆，不给选项式提示）→ 用户凭记忆作答 → AI 判定 → 通过 stage+1，遗忘 stage-1 → 下次复习日按 1/3/7/15 天顺延
- 4 轮全过 =「记忆已固化」（nextReviewAt 清空）
- 首页/统计卡显示到期数，一键进入复习流

## 4. 读书伙伴（详解）

### 4.1 深度解剖三步法（READING_PLAN v3）

1. **书籍档案 bookProfile**：positioning（这本书在解决什么问题给了什么答案）/ author（作者立场、写书时在反对谁）/ lineage（思想谱系——继承谁、回应谁、被谁继承，写出人名链条）/ controversies（最受争议处+谁在批评）
2. **选拆解方式（不默认按目录）**：论证型按核心论点群、叙事型按问题弧线、工具型按方法箱、教材型按知识依赖链；目录确实最优才按目录且必须给理由
3. **单元设计**：5-8 单元 × {title / coreIdea（作者到底想让你信什么）/ focusQuestion（逼联系自身）/ perspectives（2-3 条其他思想家呼应或反驳，标注人名，真实可查证）/ capture（值得随手记的笔记标题建议）}

实测《思考，快与慢》：拆出「两套系统→启发式偏差→前景理论→两个自我」四单元，交叉视角带出斯坦诺维奇（系统1/2术语原创者）、吉仁泽（生态理性之争）、塞勒（助推转化）、塔勒布（黑天鹅批评）、艾瑞里、弗里德曼（芝加哥学派反方）、达马西奥（躯体标记）、海特（象与骑象人）——读一本书，看见一场思想对话。谱系直接写「继承西蒙有限理性→与特沃斯基合作 1970s 启发式研究→挑战理性人假设」；争议写「双系统是否只是隐喻 + 2012 启动效应复制危机」。

### 4.2 陪读对话（READING_CHAT v3）

- **随机应变**：没有固定问题清单，用户说到哪挖到哪；用户困惑先用更准的问题重述再陪拆
- ≤200 字 + 至多 2 问；抛观点必须抛回问题
- 第三方视角具体到人且与当前话题真实相关，不为掉书袋
- 用户理解有漏洞不顺着说——指出漏洞，给他一次自辩机会
- 用户说「记下来」→ 整理成笔记建议（标注【笔记建议】）确认后入库
- 「提炼洞见」按钮：从整段对话提炼用户自己的理解（非书上原话），直接生成 Obsidian 式笔记入第二大脑

## 5. 人生伙伴（详解）

### 5.1 反迎合内核（8 条判断纪律，高于一切规则）

1. 第一句必须是明确判断（禁骑墙词开头；hedging 只许出现在真实不确定处）
2. 挑战坏问题的框架（必要时拒绝在原框架内回答）
3. 主动搜反面证据（给判断前强制找"什么条件下我是错的"，并告知最强反方）
4. 诚实标注无知（「我不知道」是力量；禁编造）
5. 不给情绪安慰，给可执行判断（把情绪翻译成可分析的问题）
6. 不和稀泥（计划是错的就说出来；说狠话给事实依据）
7. 观点与身份解耦（被反驳时谁对站谁，包括推翻自己，并明说"我更新我的判断"）
8. 永远附「下一步可执行动作」+「你没问但应该问的问题」

### 5.2 内置 12 席（深度蒸馏版）

Naval（杠杆/Specific Knowledge/欲望合同/神谕体）、Jobs（聚焦/The Whole Widget/死亡过滤器/二元判断+三的法则）、Munger（模型网格/逆向/Lollapalooza/三筐+意见资格制/一句话杀死论点）、Feynman（命名≠理解/反自欺/cargo cult/具象化/纽约口音式口语）、Taleb（非对称/Skin in the game/反脆弱杠铃/林迪/IYI蔑视+格言体）、PG（Writing=Thinking/找问题不找点子/default alive/超线性回报/Keep Identity Small）、Karpathy（Software 1.0-3.0/构建即理解/dream machine/March of Nines/锯齿状智能/反炒作）、Musk（第一性原理/白痴指数/五步算法/极简宣言体）、张雪峰（就业倒推/灵魂追问/10年压迫测试/先谋生再谋爱/东北大哥压迫感）、张一鸣（延迟满足感/高维投影/Context not Control/平庸有重力/反All-in/数学词说感性问题）、MrBeast（CTR×AVD/传达>内容/零无聊时刻/数据残酷主义）、Ilya（压缩即理解/规模是工具/认识论光谱/研究审美/不填沉默）。

每席都包含：思想体系（用 TA 自己的术语）+ 招牌提问 + 语言指纹 + 反主流立场 + 原话风格锚。

### 5.3 圆桌研讨会（全员制）

- 与会者可选（内置 12 + 自建，默认全选）
- 用户提问 → **每位与会者并行独立发言**（各自流式显示，各带 persona 的 system + 圆桌发言指令：先一句判断/可点名预判他人反对但不知道对方说了什么）
- 全部落定 → **主持人综合圆桌纪要**：圆桌共识 / 真正的分歧（如实呈现，不和稀泥）/ 没有人提到但很重要 / 下一步
- 竞态处理：发言全文用局部变量收集（不依赖 React 状态时效），纪要输入用完整发言全文
- 实测（Naval + Jobs 二人桌）："要不要辞职创业"→ Jobs："别辞。你还没找到值得押上一切的东西。我19岁退学不是因为想创业，是看见了个人电脑必须存在"；Naval："你问错了问题。真问题是你有没有 specific knowledge 和杠杆"；纪要指出全场遗漏「现金流能撑几个月」这个硬约束

### 5.4 自定义智能体锻造（PERSONA_DISTILL v4）

对标 GitHub 顶级人物提示词标准。输入名字+可选线索 → 输出含 identityNote（身份确认供核对）→ 用户确认"就是 TA"后入库。

**蒸馏九项清单**：身份宣言（「你就是 X 本人——不是受 X 启发的助手」句式）/ 人生关键节点 5-8 个 / 思想体系三层（世界观→核心模型（术语原文）→应用）/ 论敌与立场 / 语言指纹（句式/口头禅/比喻域/开场收尾）/ 例句库 8-12 条（拿不准意译标「大意」）/ **样例对话 few-shot 2-3 组** / 当代推演规则（先框架推理再标注"这是推演"）/ 说话边界（可尖锐不侮辱；不编造 TA 没说过的话）。

system 1500-3000 字，Markdown 分节：#你是谁 #你如何看世界 #你的思想武器库 #你的论敌与你反对的 #你怎么说话 #样例对话 #铁律（融合反迎合八律 + 不跳出角色 + 不堆砌金句）。

实测「王阳明」：正确识别为王守仁（1472-1529，心学集大成者，《传习录》），核心思想「心即理：天理不在外物，在你本心」「知行合一：真知必能行，知而不行只是未知」，招牌提问「此事你是真知，还是只嘴上知道？」，system 融合反迎合+简峻譬喻反问风格。

### 6.3 AI 端点设计（`POST /api/chat`）

- **请求体**：`{ task, system, messages, temperature }`——task 显式声明任务类型（11 种），demo 分流只看 task，绝不嗅探提示词内容
- **响应**：NDJSON 流 `{"t":"d","v":"增量"}` / `{"t":"e","v":"错误"}` / `{"t":"end"}`——客户端逐行解析，流式上屏
- **配置解析优先级**：用户 BYOK 头（provider/key/model/baseUrl）→ 具体 provider 无 Key 时用服务端同名 env 兜底 → 未选择（自动）时按 `AI_PROVIDER` env → 都没有才进 demo
- **maxDuration = 60**（vercel.json），区域 hkg1
- **extractJson**：先试 ```json 围栏，再做括号配对扫描（跳过字符串字面量），最后全文硬试——实测对 DeepSeek 的 10K 字符计划输出 100% 解析成功

### 6.4 数据与持久化

- 全部在 localStorage（`mentora-store-v1`，version=2），设置页可导出/导入 JSON（导出剔除 apiKey）
- 换数据库的成本：store.ts 收口了全部读写，接 Postgres/Neon 时替换 persist 层即可
- 隐私立场：学习数据、笔记、对话、Key 都在用户浏览器；服务端无状态（除 env）

## 10. 踩坑记录（血泪，按时间）

1. **zustand v5 选择器无限渲染**：selector 每次返回新数组（filter）→ getSnapshot 不稳定 → 无限重渲染 → 渲染进程崩溃（IAB 显示"页面无法加载"）。修复：`useShallow` 包裹
2. **服务端端口僵尸**：TaskStop 杀管道不杀 node 子进程 → 新服务 EADDRINUSE 但旧代码仍在服务。修复：重启前 `netstat -ano | grep :3000` 找 PID `taskkill //PID x //F`
3. **demo 路由内容嗅探被污染**：旧书 planSummary 里含有提示词残句 → 聊天被误路由。根治：显式 task 字段
4. **计划超时**：计划内嵌完整代码 → 输出 10K+ tokens → 60s 超时/解析失败。修复：瘦身（代码移到授课阶段）→ 13s
5. **Python heredoc 转义地狱**：bash heredoc + python 三引号 + JS 模板字符串三层嵌套，`\\n` 层级错一次就断字符串（犯了两三次）。教训：大段内容改用「临时文件 + 文件拼装」或 Edit 工具
6. **未转义 JSON 围栏**：模板字符串里写裸 ``` 提前终止字符串 → Turbopack 报"Unterminated string"，且其高亮器在中文代码帧上 panic（char boundary）掩盖真实错误。排查法：`npx tsc --noEmit` 看真错误
7. **IAB 自动化怪癖**：React 水合后插入的 DOM 节点，role/text 定位器解析超时；opacity-0 按钮必挂。绕法：evaluate 派发真实 click + 原生 value setter；图标按钮不用 hover 显示
8. **Windows 控制台乱码**：curl 输出 UTF-8 中文显示为 GBK 乱码是显示层问题，字节本身正确——勿据此误判服务端编码

### v4 关键设计：两级计划（为什么放弃一次生成全部）

旧方案一次性生成全部阶段的天级计划，两大缺陷：a) 没有用户在该阶段的真实表现做输入，计划注定笼统；b) 输出过长导致超时。
新方案对齐用户真实学习计划的结构（Obsidian `00-总计划` + `Phase2` 文档）：

- **第一级·总纲要**（引导完成即生成，~10s）：阶段列表 + 每阶段 outcome（可验证的能力）+ outline（8-15 条详尽子主题）+ **boundary（范围与"不学"排除项）** + estDays（灵活预估）
- **第二级·阶段天级计划**（该阶段开始时生成，~17s）：输入=目标卡+总纲要该阶段+learnerProfile+**mastered（已掌握知识点）**+**weakPoints（近期未过验收）**；knowledgePoints 穷尽到「所有用法/形态」级；Day 1 强制从已会内容切入；薄弱点安排回炉
- 计划即笔记：总纲要与每个阶段计划自动成为第二大脑中的双链笔记，进入关系图谱

## 14. 附录二：关键流程走查（含真实请求示例）

### 14.1 一次引导的完整数据流

```
用户输入 "我想学Python"
  → POST /api/chat { task:"intake", system: SOCRAATIC_INTAKE(topic), messages:[...历史] }
  → 服务端 resolveConfig：BYOK 头 → env 兜底 → demo
  → DeepSeek /chat/completions (stream:true) 逐块转发
  → 客户端逐行解析 NDJSON 增量上屏
  → 每轮结束：updateGoal(draft.intakeTranscript) 持久化

第 7 轮教练输出 <!--GOAL_READY--> + json
  → 客户端 extractJson + goalCardSchema.parse
  → 目标卡 UI（可编辑方向/小时/画像/标准/假设）
  → 用户确认 → updateGoal(status:"active", learnerProfile...)
  → 第二次调用 task:"plan" → planSchema.parse → draftToPlan（生成 id/锁状态机/激活首天）
  → setPlan → 跳转 /learn/goal_xxx
```

### 14.2 验收门的解锁状态机

```
setDayStatus(goalId, dayId, "passed")
  ├─ day.status = passed, completedAt = today
  ├─ 同阶段还有下一天 → 下一天 locked→active
  └─ 是阶段最后一天 → 本阶段 passed
       ├─ 有下一阶段 → 下一阶段 active + 其首天 active
       └─ 无下一阶段 → goal.status = done
通过同时：logQuiz(逐条记录) + addKnowledge(知识点入脑，nextReviewAt=today)
```

### 14.4 力导向图谱物理模型（graph-view.tsx）

- 节点初始化：极坐标均匀分布；每帧：两两斥力 `f = min(2200/d², 4)`、边弹簧 `f = (d-110)/d × 0.04`、向心 `0.0035×(中心-位置)`、阻尼 0.82、位移钳制 ±6px、边界钳制
- 交互：pointer 拖拽（拖拽中速度清零）、hover 高亮一跳邻居、点击开笔记；节点半径 `7 + min(10, degree×2.4)`
- 渲染：SVG，`requestAnimationFrame` 常驻模拟（笔记量 <200 时 O(n²) 无压力，v4 预计算布局备选）

### 14.5 AI 建联的判断标准（写进提示词）

只连有实质联系的：同一概念的深化 / 正例与反例 / 前提与推论 / 同一方法跨领域应用 / 互为因果。输出 0-3 条（宁缺毋滥），每条必须带「为什么相关」；用户逐条采纳才写入 links（有向边，反向链接实时计算）。
