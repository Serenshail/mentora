## 二、为什么这样设计（三条答辩主线）

### 主线 1：模型可插拔——AI 能力不绑死任何厂商

- 端点收口设计（唯一 `/api/chat`）+ providers 注册表：新增/切换模型只改环境变量，**代码 diff 为零**
- 实证：本次改造将主模型切至 `custom` 通道（用户自有推理模型），全程未改业务代码；切回华为 MaaS 同理（`AI_PROVIDER=maas` + `MAAS_API_KEY`）
- 工程价值：成本可控（BYOK）、合规可控（数据不出自有通道）、演进自由

### 主线 2：存储双通道——同一份代码跑在两个世界

| 维度 | github 通道（默认） | rds 通道（华为） |
| --- | --- | --- |
| 依赖 | 仅 GitHub API | RDS PostgreSQL（VPC 内网） |
| 费用 | 0 | 按需计费（用完即删，闲时零成本） |
| 加密 | 应用层加密 | 应用层加密 + 传输加密 |
| 切换 | `DB_CHANNEL=rds` 环境变量，无代码改动 | 同左 |
| 回退 | 删通道变量即回 | 同左 |

- 迁移安全性：密钥预检不过不开跑；对账不一致非 0 退出；**任何失败主通道零影响**
- 镜像与编排（SWR + CCE 清单：滚动升级/HPA/ELB）+ 回滚纪律（`rollback --tag`，≤10 分钟）

### 主线 3：RAG 混排检索——华为技术对产品的真实功能增强

- BM25 解决"术语精确命中"，向量解决"语义近似召回"；RRF 融合两路排名
- 未配置/失败自动降级纯 BM25——**增强是锦上添花，失败不伤功能**（fail-safe 纪律）
- 8 条单元测试覆盖融合排序与降级路径；嵌入服务端发起，Key 不落前端

## 三、工程纪律（评委常问点）

1. **凭据零入仓**：`.env*` 全部 gitignore；云上凭据走 K8s Secret/交互输入；实操日志脱敏后归档
2. **CI 五道门禁**：tsc 0 错 / lint 0 错 / 测试 81 过 7 跳 / build 成功 /（e2e 按 CI 规则跳过）
3. **健康可观测**：`/api/health` 双通道展示（`channel.db/ai` 实时反映当前通道与缺失项）
4. **全流程 AI 智能体开发**：CodeArts 五环节实践 + 真实问题修复实录 6 则（见 CODEARTS-PRACTICE.md）

## 五、费用架构（答辩加分叙事）

按需开关的云原生架构：**闲时零成本**（Vercel 免费层 + github 通道），演示/扩容时一键切换华为云线（脚本化重建 15-25 分钟），用完归零。成本模型即产品理念——"学习工具不应为闲置的基础设施付费"。
