## 2. 当前作品与应用价值

Mentora 当前是以首页工具型智能体为入口的个人学习与知识应用。面向有明确目标、需要持续推进的自主学习者。主线选高校学生从零学习一项技能，常见困难是目标太宽、计划调整会打断进度、做完任务后仍不知道能否独立运用。

参赛演示聚焦一条连续路径。学生提出「两周内用 Python 分析一份公开 CSV，每天半小时」。首页获取目标和约束，形成可执行计划。学生完成首日学习、作答并接受有依据的反馈。随后提出收缩后续范围，看到具体差异并批准，已完成课程和成绩得以保留。最后把学习成果存入笔记，在笔记库看到来源并进入复习。核心创新是智能体结合已有学习状态操作真实对象，把计划调整、知识验证和复习接到同一个流程中。

| 当前层 | 实现与证据 | 本次取舍 |
| --- | --- | --- |

## 3. 目标技术方案

浏览器 Web → 华为云 ECS 上的 HTTPS 入口与 Mentora 容器 → 模型、存储服务。SWR 保存可追溯的镜像。ModelArts MaaS 承接参赛路径的实际模型调用。RDS PostgreSQL 保存演示账号及加密学习快照，DCS Redis 承担限流、配额等短期状态。ECS 为首选，若已有可用的独立 CCE 环境可复用，同一验收标准。

复用 Dockerfile、deploy/docker-compose.hw.yml 和已有资源及镜像脚本，先核对配置与当前源码契约。码道及选定 Skills 用于真实的资源创建或关联、项目修复和部署步骤。云端用合成学习数据提供初始化脚本。交付包记录源码标识、镜像摘要、环境角色和重建步骤，凭据通过部署环境提供。现有小程序和生产账号无需迁移。

## 5. 执行顺序与分工

1. 队长核实 R00，负责阶段通知、账号信息及材料上传条件。开发负责人同时完成 R01，确定比赛版本及其来源。
2. 开发负责人用码道实施 R02、R04。云环境负责人同步做 R03，选定能够支持工具调用和结构化结果的 MaaS 模型，先跑小范围任务，再覆盖演示流程。资源账号、区域、联网入口和预算以队伍实际可用条件为准。
3. 云环境负责人完成 R05。验收人员用独立账号走 R06，与 R04 的并发、恢复及隔离结果一并签收。
4. 材料负责人并行准备 R07、R08。录屏与技术截图使用验收通过的版本。按模板补齐作品介绍和部署使用价值，队长在提交前核对证据及系统回执。

每次验收记录版本、日期、环境、步骤、预期、实际与证据位置。发现模型或云资源阻塞时标明原因和未覆盖场景。健康接口可用、自动化测试通过和用户完整体验分别作为不同证据。
