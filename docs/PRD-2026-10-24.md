## 0. 产品定位（一句话）

> **主力是学习模式：把「学会任何东西」变成日常系统；圆桌会议是锦上添花——遇到高代价决策时的多框架判断工具。**

优先级排序：学习闭环的质量 > 数据可靠 > 圆桌体验 > 其他一切。

## 1. 当前产品基线

### 1.1 四个工作空间继续保留

侧栏仍是产品的稳定信息架构，不能删除、隐藏或替换：

- 学习教练：学习目标、计划、讲义、验收、复习；
- 第二大脑：Obsidian 式笔记、双链、图谱、导入、FSRS；
- 读书伙伴：书籍档案、阅读路线、陪读、洞见；
- 人生伙伴：单人 persona、圆桌、自定义人物。

现有 CmdK、反馈、设置、账号、管理员入口也继续保留。主智能体不能吞掉这些结构化工作空间。

### 1.2 当前最可信的圆桌价值假设

圆桌最有价值的不是“16 个名人同时说话”，也不是名人 cosplay，而是：

1. 用户把一个高代价或信息不完整的问题放到桌上；
2. 不同框架先独立给出判断，避免第一个声音锚定所有人；
3. 主持人指出真正共识、真实分歧和分歧依赖的事实；
4. 补出用户没有问到的硬约束；
5. 给出条件化建议、下一步验证动作和会改变结论的信号。

这条价值链来自作者的圆桌体验和历史反馈，是**最高概率价值假设**，不是规模化用户偏好或 PMF 证据。当前没有足够圆桌埋点证明复访率、完成率或决策效果。

### 1.3 对当前实现的诚实描述

当前圆桌是：

> **多框架独立判断 + 一次主持人综合**

它还不是席位之间真正互相质询的辩论。各席位并行收到问题，彼此看不到真实发言，主持人再接收 takes 做综合。PRD、UI 和验收文案都必须使用这个准确命名。

当前已存在的基础：

- `/api/chat` 统一 AI 入口；
- `council` task 的人物/圆桌 prompt；
- 并行席位发言 + 主持人纪要；
- 会话保存和历史回看；
- 16 个席位 metadata；
- Demo/真实模型通道。

当前关键缺口：

- Demo 圆桌没有真正的席位差异和主持人语义；
- 默认全选 16 席，一轮最多约 17 次模型调用，等待和成本过高；
- 没有 runId、取消、超时、部分失败和运行级状态；
- 多轮/切会话时 live 状态可能串写；
- 主持人没有结构化校验，残缺 takes 可能被包装成完整纪要；
- 没有足够的圆桌埋点来证明“用户真的喜欢”。

## 2. 产品入口策略：侧栏优先

### 2.1 MVP 入口不变

用户从：

> **侧栏 → 人生伙伴 → 圆桌会议**

进入圆桌。

不新增第八个导航项，不把首页改成聊天首页，不把现有 `AssistantWidget` 冒充主智能体，也不把圆桌拆成新的顶级产品。

侧栏的价值是稳定、可发现、可回看。当前用户已经知道从哪里进入，不应为了追求“一个入口”而破坏已有心智模型。

### 2.2 圆桌启动页

启动页只保留完成一轮圆桌所需的最小选择：

1. **一个明确问题框**：一次只处理一个问题；
2. **推荐三席**：默认 3 个有张力的席位，而不是 16 席全选；
3. **自己选择席位**：用户可增删席位；
4. **添加自定义人物/认知工具**：沿用现有能力，不新增席位体系；
5. **输出重点选项**：例如决策、反方、遗漏约束、下一步验证。

用户按照自己的想法选择选项；模型不能擅自扩大席位、改变问题或执行外部动作。

### 2.3 长期北极星：一个对话框

“未来最好的产品可能只有一个对话框”仍然是 Mentora 的长期方向：

- 一个入口理解用户想做什么；
- 给用户可选择的学习、笔记、读书、圆桌等路径；
- 用户可自己添加或选择能力；
- 结果仍回到结构化工作空间和个人资产。

但这不是本阶段任务。本阶段不做通用 Agent Router，不删除侧栏，不隐藏四个工作空间，不把所有功能塞进一个聊天窗口。

## 3. 圆桌 MVP：只做一条价值链

### 3.1 一轮、少席、真语义

- 一次只处理一个真实问题；
- 默认 3 个互相有张力的席位，最多 4 个；
- 用户仍可手选席位，但 16 席不再是默认路径；
- 先完成一轮独立判断，再由主持人综合；
- 不追求“更多字”，追求“更少的重复、更清楚的分歧、更具体的验证”。

### 3.2 圆桌输出契约

每轮输出必须能回答：

1. **问题重构**：我们真正要决定的是什么？
2. **席位判断**：每个席位的明确判断和理由是什么？标明这是席位观点。
3. **共识**：哪些地方确实一致？
4. **真分歧**：不同结论依赖哪些不同假设或事实？
5. **遗漏硬约束**：用户没有问但会改变结论的因素是什么？
6. **条件化建议**：在什么条件下采取什么行动？
7. **下一步验证**：2–4 个小而具体的验证动作。
8. **改判信号**：什么新事实出现时需要改变结论？

主持人综合必须区分：

- 席位原话/观点；
- 主持人综合；
- 用户提供的事实；
- 模型推理；
- 尚未验证的假设。

### 3.3 Demo 与真实模型必须同语义

无 API Key 的 Demo 仍然是产品的一等公民，但不能把普通 `demoCouncil` 文本包装成圆桌：

- 三个席位必须有可辨识的不同立场；
- 主持人必须真正综合这三个立场；
- 输出结构与真实模型一致；
- 明确标记为演示模式；
- 不伪造真实名人引文、真实检索或真实用户状态。

### 3.4 运行必须可控

一轮圆桌必须有明确运行状态：

```text
pending → streaming → completed
                    ↘ partial / failed / cancelled / timed_out
```

至少支持：

- runId；
- 逐席 pending/streaming/completed/failed/cancelled；
- 主持人状态；
- 进度和耗时；
- 取消；
- 单席重试；
- 主持人失败重试；
- 切会话/新建/删除/刷新隔离；
- 部分结果不伪装成完整完成。

## 4. 目标用户任务与验证方式

本阶段不要求用户每天打开产品，而是验证五个真实问题：

| 任务 | 比较对象 | 要验证的新增价值 |
|---|---|---|
| 职业/学习方向选择 | 个人智能体、网页搜索 | 是否补出遗漏约束或反方 |
| 产品取舍 | 个人智能体 | 是否明确分歧依赖的事实 |
| 创业/项目决策 | 网页搜索 + 手动思考 | 是否给出条件化建议和验证动作 |
| 高代价个人选择 | 单一 persona | 是否降低单人盲点 |
| 一个真实但不紧急的困惑 | 不使用任何工具 | 是否值得回来使用 |

必须记录：

- 问题原话；
- 进入路径（侧栏 → 人生伙伴 → 圆桌）；
- 选择了哪些席位；
- 首个有用判断时间；
- 完整耗时；
- 圆桌新增了什么；
- 是否绕路；
- 是否比个人智能体/网页搜索更好；
- 便利度 1–5；
- 下一次类似问题是否愿意回来。

### 4.1 R7 价值门槛

五个真实问题中：

- 至少 3/5 次产生一个非重复的遗漏约束、分歧条件或更清晰的验证动作；
- 有用度中位数 ≥ 4/5；
- 用户下一次真实决策出现时愿意再次回来；
- 不允许为了证明产品有用而人为制造问题。

如果不通过，停止扩展功能，继续精修圆桌或重新定义价值，不进入通用“一句话 Agent”开发。

## 5. 明确暂缓

本阶段不做：

- 更多 persona 或认知工具；
- 通用 Agent Router / 工具编排；
- 新的 Decision Center；
- 外部执行（发信、日历、购买、发布、财务动作）；
- 自动创建/修改学习目标、笔记和阅读计划；
- 席位之间真正多轮互相辩论；
- PWA、原生 App、增长和 SEO 扩展；
- 用“每天打开”作为圆桌失败标准。

现有四个工作空间、侧栏、CmdK、单人会话、设置和数据安全能力不改。

## 6. 极窄实施顺序

### PR 1：圆桌运行可靠性

- 给 `roundtableSend` 增加 runId、AbortController 和外层 finally；
- 增加 pending/streaming/completed/partial/failed/cancelled/timed_out；
- 增加取消、超时、进度和重试；
- 修复切会话、新建、删除、刷新和多轮并发的 live state 隔离；
- 删除运行中的会话或 persona 时，阻止旧请求继续写入；
- 现有消息持久化继续使用，不引入复杂决策中心。

### PR 2：三席 Demo/真实语义对齐

- 默认推荐 3 席，用户可手选/添加；
- 为 council take/host 增加真正同语义 Demo；
- Demo 体现席位差异和主持人结构；
- 16 席显示成本/耗时提示或拒绝，不静默消耗整日配额；
- 每席/主持人显示完成、失败、耗时和重试状态。

### PR 3：圆桌体验打磨

- 会话标题包含问题摘要和时间，便于回看；
- 主持人输出短而可读，不靠 1200–2000 字堆长度；
- 清楚标注席位观点与主持人综合；
- 给圆桌问题带最小必要事实和约束，不发送全库无关数据；
- 保留用户自定义席位选项，不增加新的 persona 体系。

### PR 4：五个真实问题对比

- 完成五个真实问题记录；
- 通过 R7 后，才决定是否进入长期“一句话/一个对话框”路线；
- R7 不通过，就停止加功能，继续精修圆桌或重新定义产品。

---

## 7. 发布停止线

任何一项触发即停止扩展，不加新功能：

- 错误状态被显示为圆桌完成；
- 旧运行串入新会话；
- 同一轮重复扣配额或重复写消息；
- Demo 假装成真实圆桌；
- 三席没有可识别差异；
- 主持人编造席位观点或把模拟引文当事实；
- 五个真实问题中少于三个产生新增价值；
- 用户只会在演示时使用，真实决策时不会回来。

---

## 8. 当前决策

**现在做：** 侧栏进入的圆桌 MVP，先把运行可靠性、三席语义、Demo 真实性和真实价值验证做精。

**现在不做：** 首页统一聊天入口、通用主智能体、更多功能和更多 persona。

**未来再决定：** 如果圆桌证明“多框架独立判断 + 主持人综合”确实带来不可替代的新增价值，再把它扩展为一个能够路由到四个工作空间的统一对话框。
