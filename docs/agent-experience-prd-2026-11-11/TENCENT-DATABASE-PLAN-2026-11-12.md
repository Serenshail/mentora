# 腾讯云服务器承载数据库：执行与验收方案

日期：2026-11-12。主人提出使用已有腾讯云服务器。本文交由执行智能体实施，当前 Codex 负责规划及独立验收；本次仅只读探查服务器及源码，没有安装软件、切库或修改配置。

## 现状与结论

项目历史记录显示网站曾在腾讯云自托管，数据仍使用 Cloudflare D1。2026-11-12 通过既有 SSH 身份只读检查：腾讯云主机可访问、mentora 服务 active、2 核、内存约 1.9 GiB（当时 available 约 1.1 GiB）、根盘 50 GiB（当时可用约 32 GiB）。这是该时刻快照，不代表可承受正式负载。

当时 `postgresql`、`redis-server` 服务 inactive；`psql`、`redis-server` 和 Docker 命令未找到，systemd 无对应服务单元。不能据此断言机器上没有其他形式的数据库实例，执行者需进一步核实。

`src/lib/server/db.ts` 已有 PostgreSQL 和 Redis 适配：`DB_CHANNEL=huawei` 将主要业务数据路由 PostgreSQL、部分跨进程状态路由 Redis。名称是既有配置名，具体连接取决于连接地址，原则上可对接腾讯服务器上的兼容实例；**尚未实测验证**。不用先自行开发新的数据库系统。限流、验证码、配额和登录失败状态也必须考虑 Redis。

## 执行顺序

1. **盘点与容量**：确认腾讯主机用途、线上版本、登录入口、当前数据库通道、现有端口及可用磁盘/内存/备份空间；识别 Vercel、其他服务和小程序是否仍共用 D1（小程序本轮不改，但不能误断其数据）。记录当前健康状态，不打印密码、token 或连接串。确认当前机器并发及资源压力是否足够跑 Next + PostgreSQL + Redis；不足时在结论中提出增加内存或独立数据库的选项，不擅自购买。
2. **建立独立测试环境**：在腾讯云上为测试部署 PostgreSQL 和 Redis，限制监听/访问，独立测试账号、数据库、Redis 数据及应用进程/端口；做好服务重启和资源限制。用独立测试配置复用现有适配，不能直接替换现有网站环境。所有 fixture 只含合成数据。不得将只读/写入测试打到真实用户库。
3. **先跑原阻塞任务**：按 NEXT-ACT-UNBLOCK 文档先修测试脚本和断言；在测试环境跑 A03→A04 与 A01-E4。先 mock 模型核对审批、拒绝、冲突及恢复；再按可核实请求预算做真实模型验收。记录腾讯测试通道及完整输入、对象前后、审批、刷新和连续录像。测试环境结果只证明该环境。
4. **准备正式迁移方案**：独立盘点 D1 的用户、学习计划、笔记、阅读、会话、版本等键及加密/序列化语义，核对 PostgreSQL / Redis 两个通道的读写、TTL、原子操作、分页与同步差异；明确适配层 `huawei` 名称不代表所有腾讯设施均兼容。D1 读额度不足时先不强行导出，不编造数据完整性；制定限额或额度恢复后的导出批次和进度记录。检查探针遗留数据，只清理可明确归属的测试数据。
5. **备份与演练**：对源库取得可验证备份并在独立环境做恢复；迁移到隔离目标，按类别核对条目数、稳定 ID、完整字段/哈希、关联关系、空值和加密解密。检查账号登录、学习进度/成绩、笔记正文、历史版本、阅读与圆桌，重启应用和数据库后仍可读。演练 Redis 限流/验证码的 TTL 与跨进程原子行为。
6. **提交切换包**：列明当前/目标环境、完整迁移范围、切换顺序、预期停写窗口、验证结果、备份恢复、风险、费用和待用户查看的变更。正式数据切换按本会话既定分工由执行智能体准备具体方案，先交主人和当前 Codex 审核，再根据主人另行明确的上线指令执行。不能从“想用腾讯服务器”推导直接在现有生产上切库。

## 正式切换必须满足

- 明确数据真源和写入方。迁移前短暂停止所有写入或有经过验证的增量同步与冲突处理；最终差异核对完成才能切。禁止两个入口长期各写一个库造成数据分叉。
- 迁移前后均有可用备份和恢复演练；回退计划必须处理**切换后已产生的新写入**。仅改回环境变量会丢目标库的新数据，不算可回滚。需定义停写、反向同步或恢复后差异补偿，并明确可接受的丢失窗口。
- 上线前验证 HTTPS、数据库/Redis 不暴露公网、最小权限、凭据不入代码或日志、监控/备份以及磁盘/内存告警。项目历史文档曾记录公网 HTTP 风险，实际现状需重新核查。
- 健康检查要覆盖注册/登录、同步、重启后数据读取、失败提示与备份恢复；验证学习计划、已完成天、成绩、笔记原文、阅读和会话。远端异常不得被伪装成“账号不存在”并清除本地数据。
- 应用跑在 Vercel 等外部环境时，不能假定可访问腾讯机本地 127.0.0.1；要单独明确私网/安全连接、访问来源与数据真源。若只迁腾讯站点，其他入口应明确如何继续工作。

## 最终交付

提交测试环境拓扑、资源实测、测试账户隔离证据、兼容性结果、A03/A04/A01-E4 结果、D1 导出/目标核对、完整备份恢复演练和可执行回退方案；逐条区分未运行/失败/通过。资源或 D1 配额阻塞时继续完成不依赖它的验证，不把“数据库搬到腾讯”当成某一应用功能已经验收通过。
