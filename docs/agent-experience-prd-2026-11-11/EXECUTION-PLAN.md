# 执行任务与交接指令

本文与 PRD.md 一起交给执行智能体。规划方只写方案与验收，执行者负责实现、复现和证据。所有尚未运行的场景保留 NOT_RUN。

## 0. 执行前基线（T0）

读取 PRD、ACCEPTANCE.csv、QUALITY-CASES.json；核对当前仓库、未提交修改和实际网页版本。保存 source manifest、构建信息、模型/provider/参数与测试账户初态。复现主人截图中的发送/停止、切会话状态、计划编辑和发送后滚动问题，记录能否复现。不为重现强制安装旧版本或覆盖别人修改。

准备独立账户/数据，固定两个聊天 A/B、两个相近 Python 目标、已完成成绩/笔记、一个圆桌会话；fixture 可由脚本初始化，但正式操作阶段必须经实际 UI，不得反复 setState 修正数据后继续冒充一条链路。

代码仍变化时以快照开始，注明并发修改；共享 runtime/Store/runner 指定一个负责人。所有网络开销先记入预算，不能以一整批“案例数”冒充实际请求数。

## 1. T1 统一运行契约（CX-01/02）

涉及：agent-home.tsx、agent/runner.ts、agent/protocol.ts、store.ts、types.ts；可新增独立运行管理模块。

产出：按用户/会话/运行隔离的事件与执行状态；逐会话草稿/附件；取消与清理；至少双会话并发；重载中断恢复；对象版本冲突与 action 幂等规则。不得以多个同样的组件实例但共享单个 abort/busy 假装隔离。

先通过 S01–S10 的故障可控测试，再用真实 UI 操作 A/B；流式末尾、延迟回调、拒绝审批都要验证。这部分是所有后续 UI 的共同基础。

## 2. T2 聊天交互与固定返回（UI-01/02/03/04）

涉及：AgentHome、AgentTrace、Markdown、AppShell/页面头与设置/详情布局；复用 T1 事件。

产出：同位发送/停止；消息内过程摘要；正确计时与终态；发送强制回底、上翻暂停、回到最新；固定返回。普通知识快答不展示复杂计划。保留长代码/表格局部滚动和中文输入法保护。

通过 U01–U15；三宽度截图＋真实交互录像。过程 UI 可以先用明确标注的 fixture 事件开发，但最后必须验证实际事件来源、实际停止以及不会跨会话显示。

## 3. T3 计划修改与防空转（ACT/RUN）

涉及：tool-executors.ts、phase-edit.ts、runner.ts、get_goal/edit_phase 协议与审批卡。

产出：明确小改动按原授权执行；复杂调整精确预览/应用；稳定对象 ID、版本、取消/恢复/重复保护；任务相关工具选择与非相邻循环检测。保留现有数据成果，不重写全部学习系统。

先 A01–A11 的确定性验证，再真实模型跑“第二阶段改标题”“一周每天半小时保留成果”“原截图含糊调整”三条。不得用 dev hook 直接调用工具当作模型调用成功。若工具存在但模型不调用，仍是整体任务失败，需定位提示词、上下文或执行协议。

## 4. T4 回答质量和 token（ANS/CTX/COST）

涉及：prompts.ts、prompts-lite.ts、context builder、模型路由、请求 usage 采集。按 PRD 分层改造，保留模型配置；不要同时无记录换模型、改提示词、换评测器。

产出：任务适配提示词、关键事实摘要、相关历史/材料装配、版本化缓存、公开过程摘要和可核验 token 账单。先跑 C01–C06，再在固定基线/候选上执行 Q01–Q08。

质量优化允许两步对照：第一步同模型评估工程改动；若仍未达标，再另开明确标注的模型对比，不将差异全归功于提示词。保留原始首轮失败，禁止反复改判据直到高分。

## 5. T5 集成与交付

在同一目标构建上串联：A 长讲→B 改计划→B 方形停止→A 完成→B 重新形成方案并应用→专业页查看→固定返回→刷新确认→再次询问前序约束。不能把所有操作提前集中在同一页面以规避跨页问题。

运行相关测试、类型、lint、生产构建；一次有意义的全量回归即可，只有新修改/新失败才重复。记录存在但未解决的旧问题，不能只凭“未碰文件”判与本轮无关。

交付一个 evidence/run-id 目录、简短报告及用例状态表。报告给出哪些用户任务可实际完成、哪些未完成，工具数量只作附属信息。执行结束后交给主人，由本对话 Codex 独立验收；不要自行宣称主人已满意或全站发布完成。

## 6. 停止扩大范围的条件

发现无关模块问题登记，不顺手重做系统；数据丢失/跨用户串写等影响本轮可靠性的缺陷必须处理。D1/上游不可用时可继续确定性和布局工作，但 L3 保留 BLOCKED，不能通过更改数据注入时机抹掉持久化问题。

需要新产品决定时只提交具体差异和影响。例：供应商无法支持双会话并发、深讲成本超过门槛、跨设备冲突无法可靠检测。普通技术细节由执行者处理，不逐步要求主人批准。
