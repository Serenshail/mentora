# Mentora 智能体体验与回答质量改进 PRD

版本：1.0 · 日期：2026-11-11（北京时间） · 状态：可交付执行，未实施、未验收。

产品负责人：项目主人。规划与独立验收：本对话中的 Codex。实现：主人安排的执行智能体。本文件定义本轮行为；执行者不能用旧报告中的完成状态替代本轮验收。

配套文件：REFERENCE-ANALYSIS.md（源码研究）、EXECUTION-PLAN.md（执行任务）、ACCEPTANCE.csv（确定性场景）、QUALITY-CASES.json（固定模型样本）、EVIDENCE-CONTRACT.md（交付证据）。文件均在本目录。

## 0. 必须先读的执行摘要

本轮解决六个真实用户问题：回答不够透彻；过程只有空转标签；不同会话共用运行态；发送/停止入口不合习惯；调整学习计划只检索不落地；返回入口与滚动行为不可靠。最终交付是一条能实际使用的聊天与业务操作流程，不以新增工具数、测试总数、文字长度作为完成依据。

不得整套移植星瑶，不得整体重写 Mentora，不得安装其 Python 服务、执行其脚本或导入其用户数据。优先复用现有业务 Store、执行器和模型连接；只提取适合本产品的交互、上下文与执行机制。新增依赖必须说明现有组件为何不能完成任务及实际引入范围。

P0 是本轮必做；P1 是本轮质量改进，发布验收同样不能遗漏。功能开关只用于安全回退，不能隐藏失败后宣称达标。未获得真实模型或浏览器证据的项目标“待验”，不得把模拟测试记作真实端到端。

## 1. 产品范围与用户决定

### 1.1 范围

首页智能体及会话列表、消息输入与过程展示、相关运行生命周期、提示词和上下文装配、学习计划编辑真实链路、全站二级页面返回导航。阅读、笔记、圆桌的现有能力要保持可用；本轮不新增这些业务模块，也不继续扩展工具清单来凑覆盖率。

微信小程序、全站换肤、引入多智能体编排平台、自动购买模型或搜索服务、支付/密码/密钥代操作、管理后台新增智能体功能不在范围内。

### 1.2 本轮确定的交互决定

1. 输入框右侧同一按钮：空闲为上箭头，运行中为方形停止。不能把停止藏在输入框下方的小字中。
2. 每个会话独立运行；至少支持两个会话同时有在途任务。同会话一次一项任务，输入可编辑为草稿；运行中 Enter 不触发第二任务，也不替代停止。
3. 用户发送新消息后，只将当前聊天容器滚到底部；之后主动上翻即停止跟随。其他会话、学习页面不被抢焦点或跳转。
4. 过程与对应回答在同一消息区，折叠时也能看见当前具体阶段；可展开查看真实步骤、依据与可公开摘要。
5. 详细讲解以真正解释清楚为目标；短问题允许短答。固定九段式不是达标条件。
6. 明确、可逆的小修改按用户原指令执行一次，不要求再次批准同一确定事项；结构性重排/删除/替换需先展示方案，再批准应用。
7. 详情与设置子页面顶部有固定的“← 返回 + 上级名称”；站内返回可预测，外部深链也有合理退路。

### 1.3 优先级与继承

本文件在上述范围替代旧的“运行中全局禁止输入”“只显示固定思考标签”“固定最近 9 条足够”“所有小改动必须二次确认”等行为；不削弱旧 PRD 的对象消歧、数据保留、失败诚实、来源可靠要求。旧归档只作历史，不重算分数。

## 4. 会话运行模型与并发

### 4.1 身份与数据

建议最小逻辑模型（字段名可适配现有协议，语义必须保留）：

```text
SessionRuntime[userId, sessionId]
  draftText, draftAttachments, scrollAnchor, followingLatest
  activeRunId, pendingApprovalIds
Run[userId, sessionId, runId]
  requestId, messageId, status, startedAt, finishedAt
  modelConfigSnapshot, boundObjectIds, baseVersions
  steps, toolCalls, displaySummaries, partialAnswer, finalAnswer
  usage, error, appliedActionIds
Event: userId/sessionId/runId/messageId/seq/type/payload/time
Action: actionId/targetIds/baseVersion/preview/authorization/status/result
```

AbortController、Promise、网络句柄只存在运行管理器内，不写 JSON/同步状态。消息、最终结果、动作结果以及可公开摘要按现有持久化机制保存。密钥不进入上述记录。运行管理器生命周期独立于当前聊天组件，普通站内切页不应自动终止其他会话。

所有 delta、tool、approval、error、finally 均按发起时身份定位，不能按回调时的 activeSession 归属。序号用于拒绝重复/过时事件；正常分块必须完整保留。切换账户立即取消旧用户任务、清理运行态，禁止迟到结果写入新账户。

### 4.2 状态机

```text
idle → queued（如有配额限制）→ preparing → generating
generating ↔ executing_tool
generating / executing_tool → awaiting_approval → executing_tool
任一未完成态 → cancelling → cancelled
运行态 → completed / partial / failed
页面重载后不能恢复的在途任务 → interrupted
```

completed 只能在最终流结束且本轮承诺的动作结果已核对后出现；partial 明确哪些成功、哪些失败。终态不保留旋转图标。等待用户审批不计作模型在思考。等待上游但无内容时可显示经过时间，不伪造完成比例和“已核实”步骤。

### 4.3 并发与冲突

本轮默认至少 2 个独立会话可真正并发；若服务能力确有上限，则任务级排队并显示原因，不能由全局 busy 把另一个会话输入框禁用。不得假装同时生成，实际仍由一个全局锁串行运行。测试记录两条请求重叠区间。

同会话双击发送只接受一次。相同 actionId 不得在执行中、完成后或页面恢复后重复产生业务副作用；失败重试使用明确的恢复动作，只处理未完成部分。不得通过只在内存保存一个 Set 就宣称刷新后的幂等验收已通过。

两个会话同时改同一计划：批准方案绑定对象版本；第一个应用后，第二个旧方案必须提示冲突并重新预览，不静默重算为新方案继续执行。跨设备写入若参与本产品同步，必须在最终提交边界解决版本冲突；仅 UI 比较不足以宣称跨设备安全。

### 4.4 停止与离页

点击停止后 UI 在 200ms 内响应“正在停止”，取消当前 run 的模型与可中止请求，之后不得启动新工具/新模型请求；本地 UI 最迟 2 秒解除忙碌锁。供应商已消耗的 token 不承诺退还。

取消后迟到 delta 不写入；已完整提交的动作保留并列出。不可中断且已经提交的写入以真实结果收尾，不宣称回滚。取消审批不写业务数据。普通 SPA 导航任务可在后台继续；刷新/关闭浏览器没有服务端续跑能力时，重新打开标 interrupted，保留已保存内容并允许显式恢复，禁止自动重放未知副作用。

## 5. 输入、过程、滚动与返回

### 5.1 UI-01 输入主按钮

| 状态 | 外观与可用性 | 行为 |
|---|---|---|
| idle、无文字/附件 | 灰色上箭头、disabled | 不发送 |
| idle、有内容 | 深色高对比箭头 | 发送一次、输入写入该会话 |
| queued/preparing/generating/executing/awaiting_approval | 同位置方形停止、可点击 | 取消当前会话任务/审批 |
| cancelling | 停止中反馈、防重复点击 | 保留草稿 |
| 终态 | 回到箭头 | 根据草稿决定可发送性 |

主按钮点击区至少 44×44 CSS px；有 aria-label“发送消息”/“停止当前回答”、键盘可激活、焦点可见。中文输入法组合过程中 Enter 不发送。运行时用户可继续编辑草稿，但 Enter 不提交新任务，方形按钮仍保留；本轮不做同会话消息队列。待审批卡有批准/拒绝按钮，不与停止混淆。

### 5.2 UI-02 过程与正文

一条回答内从上到下为：过程摘要行 → 可展开步骤 → 回答正文 → 结果/来源。单点快答允许只有正文，不能机械增加流程。

运行中折叠标题显示最新有证据的事件，例如“已定位 Python · 第二阶段，正在准备调整方案”；用户可展开。展开箭头始终可发现，不只在悬停时出现。过程正文 14px 以上，回答正文 15–16px，不能用低对比 11px 作为唯一状态入口。

允许的信息来源：工具开始/完成/失败事件、明确的执行计划、真实结果摘要、供应商明确提供并允许展示的摘要。必须标明来源类别。原始内部推理不直接暴露；正文中的 `<thinking>` 或引用资料中的类似标签不能自动当作可信思考事件。没有摘要支持时展示真实执行事件；只有心跳则说“正在等待模型响应”，不额外调用模型编造思考。

摘要最长两行、中文为主，不滚动播报虚构阶段。展开步骤可查看对象、动作、结果和错误恢复。完成后停止动画、显示耗时与实际终态，可再次展开。耗时从相应事件计时，不能拿准备请求的几毫秒作为模型思考时长。

模型流式正文和工具协议分别存储/渲染。合法解释段落不能因下一次 tool_call 被清空；内部 JSON 不进入正文。最终消息必须与被接受的流式内容相符，修正事件按版本处理，不能简单依赖“字符串更长就一定正确”。

来源区区分“搜索失败”和“已成功读取的网页”：有真实读取结果可以引用；只有搜索摘要不冒充全文。没有联网证据时对时效结论明确未核实，不编 URL。原始错误细节放诊断区，面向用户说明影响和下一步。

### 5.3 UI-03 滚动

状态分 followingLatest / browsingHistory，并按会话保存。主动发送或点击“回到最新”强制回底，清除旧的向上滚动意图；消息插入完成后的下一渲染帧执行，不能在 DOM 尚未更新时滚到旧底部。普通流式变化仅在 followingLatest 下跟随。

滚轮上翻、触摸上翻、PageUp/键盘上翻立即退出跟随；展开过程、图片加载、表格布局变化不能误判为用户要求回底。browsingHistory 时显示“回到最新”按钮与新内容指示。切换会话恢复该会话滚动位置；首次打开可定位最新。后台会话完成不改变当前会话滚动，也不导航到首页。

仅操纵消息滚动容器，不对 window 或学习页执行全局 scrollIntoView。连续 delta 合并到渲染帧，避免大量 smooth scroll 队列。手动滚动与新 delta 同帧的竞态纳入验收。

### 5.4 UI-04 固定返回

页面实际滚动容器顶部固定导航：返回入口＋当前页面标题，具备不透明/足够遮挡的背景和正确层级，不遮挡正文/模态框。返回区至少 44px 高、文字可读，不以“更亮”替代对比度检查。

学习详情→学习列表；阅读详情→书架；笔记详情→笔记列表；设置子页→设置；设置一级→进入设置前的有效站内页面，否则回首页。有效站内来源带列表筛选/滚动恢复；外部深链无历史时采用以上兜底，不能一退离开产品。浏览器自身后退/前进保持可用，不创建循环历史。

在 390/1280/1440 宽度分别滚到顶、中、底检查；200% 缩放和 320px 做关键控件可用性补查。

## 6. ACT：真正调整计划，不再查询到预算耗尽

### 6.1 对象优先级与路径

明确用户指定 ID/名称 → 当前会话已确认对象 → 专业页显式携带对象。多个候选时询问；不能以全局第一个 activeGoal 替代用户指定对象。自然语言阶段序号解析为当时目录中的稳定 phaseId，并在操作前显示阶段名。

给定“把 Python 第二阶段标题改为文件与数据处理”：读取对应项目和当前阶段 → 定点修改 → 读回验证 → 给出结果与计划入口。用户这条指令就是对确定小改动的授权；保留动作审计和恢复能力，不再重复批准。

给定“第二阶段改成一周、每天半小时，保留完成内容”：读取目标/阶段/相关已完成证据 → 生成具体草稿 → 展示旧/新标题、目标、日目录、时间约束、进度影响 → 用户批准 → 版本核对 → 原子或受控提交 → 读回验证 → 精确入口。不能先生成后偷偷应用。

给定截图原话“关于我的那个 Python 计划，我想调整一下他的那个计划，就是他的第二阶段，我想直接给他调整一下”：已有明确上下文就用；若调整方向未知，最多一轮聚焦问题询问要改什么。用户若补充后仍存在实质歧义可再问，禁止机械“一次之后必须执行”。不问无关背景、不反复检索第二大脑、不凭空决定修改内容。

### 6.2 预览与数据保护

预览必须绑定 targetId/baseVersion；关键差异可完整展开，不以截取前 450 字替代完整方案。包含已完成/跳过/掌握记录的影响说明。取消不写入；批准只应用被批准草稿；恢复只回退计划结构，不覆盖其后成绩/笔记。页面和智能体调用同一业务提交规则。

### 6.3 无进展控制

对规范化工具名＋参数＋对象版本建立本轮读取记录。相同状态的相同只读结果优先复用；版本变化后失效；失败结果不缓存为成功。工具结果只保留与任务相关的结构化字段及必要原文，不能压掉 ID、版本、错误、用户约束或验收证据。

识别非相邻重复与换参数空转：定义任务进展为获得必要缺失信息、确定对象、形成/更新草稿、审批或成功提交，不能仅凭调用次数/结果长度变化宣称有进展。确定修改路径中，连续两轮模型调用没有新证据或动作进展时停止相同策略，转为一次聚焦澄清或有依据的失败说明。研究任务合理读取新来源不应被这个业务修改阈值误杀。

预算耗尽给出“已做/未做/是否写入/可继续什么”，不展示泛泛“继续就好”。不得只调大 MAX_TOOL_ROUNDS；统计实际 provider 请求数（含额外收尾调用），不能以 for 循环索引当调用预算。

## 7. ANS/CTX：提示词与上下文工程

### 7.1 提示词组织

稳定规则：准确、对象边界、来源、结果诚实、语言与授权。任务模块：直接问答、详细教学、资料研究、业务操作。动态块：当前目标、已知背景、当前对象及版本、必要材料、未完成动作。工具定义按任务加载，跨域请求允许明确升级工具集合，不能被分类器锁死能力。

日常问题不强制九段式、不默认出题建目标；用户明确“详细/逐行/没懂/换例子”或继续教学上下文时提高解释深度。深讲要解释目标、核心因果、关键中间过程、边界和适用条件；具体结构因题而定。用户只要结论时按要求收敛。

提示词中“简洁”“不复述”不得压掉教学所需的因果和必要前情。不要复制星瑶的人设、Shell/文件工具规则或无关计划编排命令。不要靠要求模型打印全部内部推理提高质量；用户得到的是充分、可核验的解释。

### 7.2 关键上下文

输入清单至少区分：本轮原话、最近相关对话、确认事实摘要、选定业务对象、材料原文、工具事实。用户明确事实保留来源 messageId、时间、是否被后来更正；“每周 3 小时”更新为“每周 5 小时”后使用后者，不能都视为当前值。摘要不能把猜测、模型建议或用户否定项写成用户事实。

不同会话不自动共享草稿、材料或个人推断；允许共享的长期用户偏好必须有来源和明确作用域。不得读取另一个会话的思考、工具结果来补当前回答。

历史选择按预算和关联而不是固定条数。最近相关轮次保留原文，较旧但仍有效的约束进入摘要；代码、数值、引用和用户关键原话按需保留原文。第一次部署优先用确定性事实提取/选择；确需模型压缩时，达到水位或发生显著变更才触发，不能每轮多调用一次压缩模型。

建议起始上下文预算：常规输入上限 8k token、详细教学/材料上限 16k；有效上限还要扣除供应商输出预留和安全余量。短答输出建议上限 1k、详细教学建议 6k；这些是首版可配置工程值，不是要求模型写满。材料超限时分段并标明范围，不静默丢弃核心部分；不能为了上限删掉唯一决定正确性的代码/约束。

### 7.3 回答质量标准

以原用户四段 C 语言讲解样例的教学优点为参考，纠正其中事实问题，不逐字模仿。详见既有 TEACHING-REFERENCE.md。

答案必须做到：结论正确；因果解释足够；例子和状态可复核；适配用户已有背景；组织便于阅读。用户说“不理解”时改变解释方式并定位卡点，不原封不动重复；用户只问概念时不强行推进项目。

Q01–Q08 每题五维各 0–4 分：事实正确、完成请求、解释/推演或简答充分性、上下文/依据、表达可读。0=缺失或严重错误，1=大部分不达标，2=可用但有实质遗漏，3=满足关键要求有小瑕疵，4=完整清晰且无明显多余内容。短答的解释维度评价是否足够直接准确，不要求长篇。

建议本轮质量门槛：新版本 8 题平均至少 18/20；每题至少 16/20；事实正确维度每题至少 3；无关键错误、虚构来源/执行或跨对象泄漏。Q01/Q03/Q04 教学重点由主人额外判“愿意使用/仍需改进”；三题均需愿意使用才能称教学达到本轮要求。18/20 是评分门槛，不等于生产准确率 90%。

## 8. COST：预算与效果共同验收

不额外为动画或每个过程摘要调用模型。普通确定知识简答目标一次模型请求、零无关工具；教学一般一次生成，确需取资料再增加；定位明确的小改动目标为读取→执行→核对，不能出现与目标无关的多次笔记检索。

按同题、同模型、同参数、同初态比较旧/新：输入 token、输出 token、缓存计费 token（供应商可得时）、模型请求数、工具请求数、首个可见反馈时间、首段正文时间、总时间及是否成功。缺失 usage 标 unknown；字符估算明确 estimated；不能报 0 token。未提供单价时不编人民币成本。

第一轮质量对照是 8 个案例的旧/新各一次，共 16 次案例执行（多轮案例包含多条模型请求，不能说成只消耗 16 次请求）。运行前冻结总额/配额与可用预算；若没有金额预算，先采用最多 48 次实际模型 provider 请求作为本轮默认保护上限，达到后停下保存结果，不静默继续花费。工具内部触发的模型请求、摘要压缩模型请求、失败请求及重试均计入这 48 次；纯本地工具和搜索等非模型请求单独计数并计入费用账，不混作模型请求。真实模型并发专项另行登记预算，不混入质量成绩。

成本通过要求：简单问答请求数不增加且输入 token 中位数不高于基线；深讲以质量先达标，输入 token 中位数不高于基线 1.2 倍。深讲输出可以增加但必须与解释收益对应，报告质量分/完成成本；不许削掉关键解释来达成成本指标。超过阈值标需优化或提交明确例外，不伪造节省率。

缓存作用域包含 userId、会话或授权共享范围、对象 id/version、查询参数与权限；跨用户不可复用私有数据。写入/同步版本变化时失效。稳定前缀只包含真正稳定信息；不能把具体厂商缓存命中当必然效果。

## 9. 验收、交付与失败归类

### 9.1 三层证据

L1：确定性逻辑测试（事件归属、停止、重复、版本、滚动状态、上下文选择）。L2：真实浏览器＋隔离业务数据（输入、审批、导航、刷新、键盘及三宽度）。L3：真实模型完整任务（教学、计划修改、两会话并发、过程与来源）。L1/L2 通过不能替代 L3；直接 dev hook 调 executeAction 只能算执行器集成，不能算模型会选择工具或用户完成了审批。

实际交付页面必须记录 build/version、工作树清单哈希、URL、模型配置、运行时间。若与主人截图版本不同，先说明差异并在目标版本复测；不能以“本地通过”关闭问题。

### 9.2 冻结与结果

执行前冻结脚本、输入、初态、期望、模型参数、提示词、预算和代码哈希。先保存完整首轮结果，再分析。重试独立记录，不替换首次失败。评测器缺陷登记后发新版本，新旧结果不直接比较、不回填。

结果仅 PASS/FAIL/BLOCKED/NOT_RUN。工具错误归为上游需请求级关联日志，不凭空回答或红色工具徽章猜测；环境阻塞仍影响用户端完成率。报告全样本分母与条件分母，不能只公布排除失败后的高分。

### 9.3 验收责任

执行智能体提交证据，主人转交本对话；Codex 独立核对关键源码/请求/业务状态与画面，检查是否完成用户任务，不只复读报告。浏览器或服务不可用时明确标无法独立验证，不承诺绕过访问限制。最终“满意”还需主人对参考教学题和交互演示确认。

若需求含糊导致偏差，由规划方修订；若实现违反明确条款，按实现缺陷处理；若模型/服务不满足门槛，按能力或依赖问题记录。责任定位不影响修复闭环，不把所有失败统称环境问题或测试脚本问题。

### 9.4 完成定义

所有 P0 场景通过；P1 质量与成本门槛满足或获得主人明确例外；无会话串写、重复执行、错对象修改、数据丢失、伪造过程/成功。原用户截图场景在目标版本真实复现并验证改善。提交必要回归、类型、lint、生产构建及证据清单。任何未执行项不能记为整体验收完成。

## 10. 实施约束与恢复

按 EXECUTION-PLAN.md 小批推进，每批形成可演示成果；关键共享运行层指定一个写入负责人，避免多人并发改同一协议。可以做独立 UI 和测试任务，但必须先统一事件/身份契约。

第一批开始前保存基线和现有未提交改动清单；不可 stash/reset/覆盖其他智能体工作。新数据字段兼容旧会话，默认缺省安全，加载时不生成假运行状态。关闭新功能不得删除历史数据或重放动作。回退须停在安全终态，并保留已提交的真实变更与证据。

记录每批对输入/上下文/事件/业务对象的影响，避免只报“新增 N 个工具、通过 N 个测试”。本轮不部署、不提交他人改动，发布由主人另行安排。
