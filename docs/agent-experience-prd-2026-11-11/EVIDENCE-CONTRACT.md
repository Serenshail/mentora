# 验收证据、评分和回收格式

## 1. 每次运行的交付目录

```text
evidence/<run-id>/
  manifest.json         代码/提示词/脚本/fixtures 哈希、日期、构建、模型参数、预算
  results.csv           caseId、PASS/FAIL/BLOCKED/NOT_RUN、原因、证据路径
  requests.jsonl        请求 id、所属会话/运行、起止时间、usage、错误、重试关系
  events.jsonl          公开过程事件、序号、归属、工具状态（不含密钥/原始内部推理）
  answers.jsonl         完整用户输入、材料引用、完整可见输出、首次/重跑标志
  before-after.json     脱敏后的目标对象及字段差异、审批 actionId、对象版本
  quality-scores.csv    五维分数、具体缺失/错误、用户对重点教学题的判定
  screenshots/          同题三宽度；标明样例还是实际模型内容
  videos/               切会话/停止/回底/返回/修改计划实际连续操作
  checks.txt            相关测试、类型、lint、构建命令及真实退出码
  report.md             范围、结果、成本、限制、待修与恢复办法
```

证据保存在独立新目录，不覆盖旧文件。账户 ID 可散列但必须能区分 A/B 和用户作用域；不保存访问令牌、cookie、API key 或无关个人材料。浏览器录像不要录入密钥设置。

## 2. manifest 最小字段

runId、startedAt（带时区）、targetURL、buildId、head、dirtyFilesManifestSha256、promptSha256、fixturesSha256、runnerSha256、model/provider、temperature、reasoningSetting（未配置记 default/unknown）、context/output limits、currencyBudget（可 unknown）、providerRequestLimit、accountFixtureId、browser/viewport、真实/模拟标志。

在用户实际访问的构建复测：本地、预览、部署地址不能混为同一版本。HEAD 相同但工作树不同不是同一候选。

## 3. 功能结果

每条 ACCEPTANCE 用例附：初态、原样输入、操作、观察到的 UI、实际业务字段、刷新后的结果、是否重新注入、请求关联。采集缺失不能记 PASS。若结果属于部分成功，拆明成功/失败动作，整条是否通过以原标准判断。

模拟 LLM 可以验证隔离和错误路径，但 L3 必须通过实际 UI 发起自由输入，观察模型选择工具、用户审批及对象结果。只调用工具或只检查按钮存在不得记端到端通过。

UI 证据至少包括：A/B 同时运行请求重叠，B 停止而 A 继续；发送时从历史位置回底；流式上滚不会被抢；后台完成不会跳页；复杂计划审批前后与刷新状态；页面滚到底部时固定返回仍可用。

## 4. 质量评分方法

QUALITY-CASES.json 是新设计的验收样本，不冒充真实用户历史。Q01/Q03/Q04 借鉴用户原教学参考的行为要求，不复制其错误结论。

五维各 0–4，评分者必须给出对应答案段落或缺失项。题目的 mustInclude/forbidden 是核对材料，不用统一字符数或关键词凑合格；可以换表达，只要语义正确。重点知识错误可直接否决该题，不能用排版高分补偿。详见 PRD §7.3。

旧/新输出随机标成 X/Y，隐藏模型/版本后评审。评审完成再揭示版本。正确性由可复核计算、源材料或实际状态核对，教学喜好由主人判定，Codex 汇总独立结论。若答案确实充分，不因“没有九段式”扣分；若答案只是更长，不因此加分。

每题第一次输出为正式观察。模型不稳定时先保留失败，若复跑则新 runId/attempt，并报告稳定性，不拿最好一次替换首轮。

## 5. 成本账本

每次模型请求独立记 inputTokens/outputTokens/cachedTokens、usage 来源（provider/estimated/unknown）、工具调用数和用途。阶段摘要若新增模型调用必须单列，不能隐藏在“基础设施”。输入缓存计费规则按实际服务配置记录，不套用其他供应商。

比较相同题、相同模型参数、相同初态。深讲输出变长可能合理；先核对质量，再评估是否有重复解释。分别报告短答/教学/研究/操作，不能用大量廉价短答稀释失败操作的成本。

## 6. 独立验收步骤

1. 校验 manifest 对应交付文件、证据未缺项、首轮与重跑没有混合。
2. 定点读取关键改动：身份隔离、取消和幂等、版本冲突、摘要与滚动、上下文装配。
3. 核对最重要的实际操作录像和真实对象前后状态，必要时在允许的环境独立复现。
4. 对 Q01–Q08 完整输出重新核对事实与教学质量，并结合主人重点题判定。
5. 给出“通过 / 条件通过（明确范围） / 不通过 / 无法验证”，列具体未满足条款与下一步。

独立验收不是保证第三方模型永不出错；PRD 的责任是把目标、边界、失败处理和证据要求说明白。没有访问能力或服务故障时诚实保留待验，不凭执行智能体自评盖章。
