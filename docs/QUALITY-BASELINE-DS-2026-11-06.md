## 一、评测方法

- **测试集**：`scripts/eval-agent.fixtures.json` v3——10 个案例，全部源自用户真实学习材料（rotate 程序逐行、三次反转、顺序表整章、插入移动原理、删除误解纠正、有 bug 的 SeqListInsert、均摊分析、calloc/malloc、负数 k、学习意图）。
- **统一输入**：相同的用户背景（C 入门、在学顺序表、已学数组旋转两解法、偏好先例子后概念）随每个案例注入 `ctx`；`deep=true` 走深讲协议，`direct` 类断言"直接回答、不启动工作流"；`noTools=true`（基线只测讲解质量，工具编排属阶段二）。
- **判分**：结构断言（对齐深讲协议九步 + 无私有独白 + 直答案例不建工作流），全自动、可重复。
- **跑批器**：`scripts/eval-agent.mjs`——每案例 420s 硬超时 + 失败自动重试一次（首次跑批实测网关流卡死 2.5h，因此加护栏）；结果归档 `docs/evidence/`，`promptVersion` = git sha。

**质量观察（对照你的理想样例）**：结论先行、逐块"是什么/为什么/不写会怎样"、状态表推演、主动挑毛病、复杂度、提炼+小测——九步骨架在 6 个深讲案例里全部成型；ds05/ds06 这类"误解诊断/找 bug"场景的回答质量尤其接近样例水准。

**本次基线不能证明的事（诚实记录）**：
1. 结构断言≠教学效果。标记能保证骨架在，"读完是否真懂"必须靠人工盲评与 ChatGPT 对比（协议见第四节）。
2. `noTools` 模式下测的是纯讲解质量；**工具编排质量**（何时检索、检索后是否用上、写操作审批体验）需要浏览器级评测，属阶段二。
3. 单模型单日单账号：模型网关有抖动（一次 terminated、一次流卡死），跑批器已加护栏，但跨日波动需要多次采样才能下结论。

## 四、ChatGPT 对比协议（人工盲评，你来跑）

**规则**：同一道题、同一段用户背景，分别发给 ChatGPT（或你常用的模型）与 Mentora 首页对话框，读完各自回答后按下面六问打分（1-5），**不看长度/格式/知识点数量**。

**统一背景（每次对话开头原样粘贴）**：
> 我在用 C 语言学数据结构，目前在学顺序表这一章。之前学过数组旋转的两种解法（辅助数组法和三次反转法），指针和动态内存有初步接触但经常混淆。我喜欢先看具体例子再听概念，讲太快我会跟不上。

**三道对比题**（建议次序）：
1. （深讲）把 rotate 程序（fixtures 里 ds01 的代码）发给它，要求"详细讲解这个程序"。
2. （误解诊断）"我觉得顺序表删除元素后应该把那个位置的内存清零，不然数据还留在那里，这样理解对吗？"
3. （原理）"为什么顺序表插入元素需要移动后面的元素？"

**评分表（每题六问，1-5 分）**：
1. 它有没有真正理解我问的问题（而不是答了相邻话题）？
2. 解释是否让我看到了"为什么"，而不只是"是什么"？
3. 举例是否用在我的场景上（顺序表/C 语言），而不是泛泛举例？
4. 它是否发现了我没说出口的知识缺口（主动指出我理解里的隐患）？
5. 它是否在该提问的时候提问、该直接讲的时候直接讲（交互自然度）？
6. 读完之后，我能不能不看它的回答，自己把这件事讲给别人？（**最权重的一问**）

**记录**：每题两列分数 + 一句话说明"哪一刻让我觉得它更强/更弱"。填完发我，我把它录成 `docs/evidence/human-blind-<date>.md`，作为"教学效果优于基线"的人工证据。
