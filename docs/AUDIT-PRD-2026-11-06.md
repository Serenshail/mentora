### 1.2 关键调用链（现状，非 PRD 设想）

```
用户 → AgentHome.send()
  → wantsDeepExplanation()（客户端正则判 deep）
  → buildCtx()（store 快照：activeGoal/knowledgeCount/dueReviews/books）
  → runAgent() 循环 ≤5 轮：
      streamChat(task=agent, args{ctx, deep, personal?})   ← personal=记忆注入（v24.0.11 恢复）
      → collectCalls（原生 tc 优先，围栏兜底）
      → executeTool：读=直接执行（含 web_search/read_url 走服务端守卫）
                    写=draftAction → requestApproval（审批卡队列）→ executeAction
      → 结果回注（原生 tool 角色消息 / 围栏 toolLog）
  → appendAgentMsg(answer + meta{plan,tools,citations})

页面直连工作流（不经 agent）：
  /learn/new → intake(≤2 轮追问+assumptions) → plan(master/phase 两步) → /learn/[id]
  /learn/[id] → lesson → quiz-grade（证据强制）→ mastery 推进 → review(FSRS)
  /read/[id] → 五模式对话（retrieveEnhanced）→ 三重验收 → 洞见 → 知识库
  /council → take（并行席位）→ host 综合
```

## 四、回答质量评测纪律（回应你的第三条要求）

**规则：任何 prompt / 模型 / 上下文改动的 PR，必须附四件套——测试案例、修改原因、前后对比、评估数据。没有这四件套的 prompt 改动一律不许合入。**（包括我自己。）

### 4.1 形态：扩展现有容器，不新建系统

- **测试集**：`eval-<task>.fixtures.json`（从 `scripts/eval-grade.mjs` 的 8 个夹具起步，格式照抄：answers + expect 多值集合 + caseId + notes）。第一批：quiz-grade（已有 8）→ review-grade（新 5-8）→ 深讲（新 5，用你提供的 C 语言数组旋转样例做金标准）→ 意图四路（新 30）。
- **跑法**：`npx vitest run eval-<task>`（`skipIf(!E2E)`，同 `e2e.local.test.ts` 的门）；逐 case 调真实 `/api/chat`，与现有契约一致。
- **归档**：每次运行追加写 `docs/evidence/eval-<task>-<date>.json`：`{promptVersion(git sha), task, passRate, perCase[], notes}`——**前后对比 = 两个 json 的 diff**。
- **prompt 版本关联**：promptVersion 直接用 git sha（prompt 在 git 里，sha 即版本），不引入新版本号体系。
- **红线**：关键事实/代码错误不得被其他维度高分抵消（照抄 quiz-grade 的 normalize 思路：evidence 缺失直接降级）。

### 4.2 流程

```
改 prompt 前先跑基线 eval → 存档 A
改（commit message 必须写修改原因）
跑同一 eval → 存档 B
PR 描述附：原因 / A.passRate vs B.passRate / 逐 case 差异
B < A 且无明确理由 → 不许合入
```

### 4.3 已有的可复用资产（不要重造）

`scripts/eval-grade.mjs`（夹具格式+阈值退出码）、`e2e.local.test.ts`（真模型 12 场景+skipIf 门）、`normalizeQuizGrade/normalizeReviewGrade`（证据强制纯函数+12 测试锁）、`chat-usage` 双写（成本侧已完整）、RAG `trace` 结构（已造好未接线——接上就有检索质量数据）。

## 六、给 PRD 的最终意见

1. **架构层同意、接口节反对**：四层架构就是现状的抽象，照做零成本；`WorkflowRequest/Result` 一节删掉，用工具注册表。
2. **P0 清单减半**：八项里"审计/上下文分层/模型日志"大半已存在，真正的新增量是意图四路判定、工作流交接工具、评测体系三件。
3. **质量优化必须评测驱动**（第四节纪律）——这条比 PRD 第六章本身更重要，建议直接写进仓库的 CONTRIBUTING 约定。
4. **PRD 未提但已在进行的事**：会员/激活码体系（并发进行中）、阅读 v25.0（已完成）。后续 PRD 更新前先同步这两块的状态，避免再次出现"覆盖丢失"类事故。
