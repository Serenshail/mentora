# Mentora 安全检查与修复记录（2026-11-20）

范围：本地工作区源码、两个线上首页和健康检查的只读请求。尚非完整渗透测试；本地源码与线上构建尚未对应。未进行生产写入、扫描或账户尝试。

## 按优先级

1. **紧急 / 已在线上观察到：腾讯云地址明文 HTTP。** 首页经 HTTP 返回 200，HTTPS 连接未成功。通过此地址传输的登录信息、会话和用户数据可能被窃听或篡改。需为腾讯云配置可信 HTTPS 地址和证书，并验证所有客户端，再考虑跳转。Vercel 地址 HTTPS 可访问，但两站构建不同，数据和功能是否一致尚未确认，不能直接跳转。
2. **高 / 两个线上站点均已修复：重置密码口令判断泄露。** 修复前先比较新密码和原密码，重置码无效者可从响应区分猜测是否正确。已移除该比较，允许重置为相同密码；无效重置码不会修改密码。见 `src/app/api/auth/reset-password/route.ts`。
3. **高 / 两个线上站点均已修复：重置码可能重复使用。** 已改为利用存储层原子占位，确保同一码并发使用最多成功一次；不再删除原始记录，以免误删刚重新发放的码。占位记录会累积，后续需要安全清理；存储失败时拒绝重置，密码写入失败后需重新发码。
4. **中 / 本地代码确认：注册没有邮箱所有权验证。** 现有实现验证域名可投递且要求激活码，但不证明使用者控制该邮箱。可能导致有激活码的人抢先注册他人的未注册邮箱；产品需明确邮箱验证方式。
5. **高 / 已修复腾讯云线上：3000 端口直接可访问。** 应用现仅监听 127.0.0.1:3000，公网尝试未能到达应用，Caddy 网站入口仍可访问。直接使用公网 IP:3000 的旧客户端需改用网站入口。服务器的 2019、6379、6380 和 5433 监听本地地址；未检查云安全组全量规则。
6. **待核实：账户隔离、线上依赖漏洞和暴露面。** 本地 sync、tasks、memory、reminders 使用会话身份定位用户数据，不能据此证明所有接口均安全。需隔离测试账户、线上版本清单、服务器监听与防火墙配置，再检查横向越权、依赖公告、配置文件、端口及生产构建产物。

## 对原方案的核对

- 本地 `next` 为 16.3.4；CVE-2025-29927 对应旧版本，线上实际包版本尚未核对。
- 本地没有 `/api/auth/send-code`；注册并非原方案所称的邮箱验证码流程。
- 本地 `src` 未发现 `use server` 声明；这不能证明线上没有 Server Actions。
- 公网健康检查：腾讯云构建 `fa7816e`、Vercel 构建 `64cee78`；仅反映检查时响应，不能证明两站数据相同或源码一致。
- 未登录页面拦截只检查 cookie 是否存在；敏感数据仍须在各 API 及数据层独立核验身份和权限。
