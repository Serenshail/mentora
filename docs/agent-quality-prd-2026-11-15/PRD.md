# 产品需求

## 1. 目标、范围与不可退化项

目标：用户能理解回答、核对依据、看清实际进展，并顺畅接续操作。范围为首页对话、学习教练答疑/讲义、阅读讨论、人生伙伴；首页滚动是本次强制修复范围，学习教练不改成首页的自动回底策略。

保留写操作审批、账户/会话归属、停止与失败语义、真实证据、现有用户资产和备份；不得为显示过程新增一轮“编造思考”的模型调用。只交 PRD 的本轮不实施产品变更；下一实施者按本包分批执行。

用户口中的“思维链”转成可验收的产品定义：**消息内的执行过程、已公开的简短思路摘要、工具依据与结果**。不要求取得或逐字公开模型隐藏的内部思维链，不让模型在正文写长篇内心独白。用于教学的计算步骤、算法推导与例子应正常充分展示，不能以“隐藏推理”为由删除用户需要学习的解释。

## 2. 过程显示需求

### P01 消息内部只有一个主过程区

同一条 assistant 消息中依次为：状态标题 → 可展开过程区 → 正文 → 结果/引用。右侧工作台只提供辅助导航，不承担唯一过程显示。桌面和手机均能在消息处看到。标题正文最小 14px，正文沿用 16px 阅读规范；按钮可键盘操作，触屏点击区域至少 44px，aria-expanded 与内容一致。

执行中默认展开真实步骤，完成后默认折叠为“已完成 · N 个步骤 · 耗时”，可再次展开。纯等待且无步骤时显示等待状态与实际耗时，不渲染空白“过程”面板。用户主动展开/收起后，不因每个增量重置选择；切换会话保留各自选择。过程超过约 240px 时区域内滚动，用户向上读过程不被新增事件拉回；全页和消息区不横向溢出。

### P02 事件与内容来源

规范事件结构：schemaVersion、eventId、accountId（客户端本地归属，不对外展示）、sessionId、runId、seq、timestamp、kind、source、status、label、detail、toolCallId（可选）、durationMs（可选）。

kind 包含 phase、tool_started、tool_completed、tool_failed、approval_required、approval_resolved、public_summary、warning、terminal。source 为 runtime、tool、provider_public_summary；供应商单纯 reasoning_content 不得自动映射为 public_summary。心跳不建新步骤，只更新 lastTransportAt。

工具开始/完成绑定同一 toolCallId 更新同一行，不重复追加。乱序按 seq 合并；重复 eventId 幂等；旧 run 的迟到事件不能覆盖新 run。详情只保留安全摘要，移除 Key、身份凭据、敏感工具参数和原始堆栈。不得将完整工具回包塞到过程面板或送回模型第二次。

只在供应商明确提供面向用户的公开摘要且适配器可确认语义时显示该摘要；其他情况显示 runtime/tool 的实际活动与依据。无摘要不算失败，凭空造摘要算失败。只在正文提供正常面向用户的简短解释，不额外请求模型生成过程。隐藏推理不存 localStorage、云快照、账本、日志或报告。

### P03 无假进度、无永久转圈

状态：preparing → waiting_model → answering/executing_tool；executing_tool 可回 waiting_model；awaiting_approval 单列；终态 completed/partial/failed/cancelled/interrupted。每个终态都停止所有相关 spinner；一席失败或审批拒绝不能显示为全成功。等待审批不计为模型无响应。

记录 startedAt、lastTransportAt、lastProgressAt；心跳只更新 transport，不代表业务取得进展。10 秒仍无正文/工具/公开摘要时显示“模型仍未返回内容，已等待 N 秒”；30 秒无业务进展再显示“等待较久，可停止或重试”，不能暗示已在读取某个对象。已有服务端空闲、240 秒流阶段、8 MiB 限制保留，增加客户端总等待保护与断连收尾；每任务超时值集中配置，长讲义不套短查询的 30 秒强退。

超过总预算或连接中断：进入 partial/failed，保留已有正文并标“不完整”，提供明确重试。重试必须是新 run，旧写操作不得自动重放；已完成写入与失败读取分别显示。刷新只标 interrupted，不自动续费式重发模型或重做写入。

## 3. 回答质量与上下文需求

### Q01 任务模式统一

统一 normal、deep_explain、re_explain、action、clarify。入口传递 mode 与判定依据，服务端校验并执行；已有 decideExplainDepth/wantsDeepExplanation 先复用、补齐，禁止又建第二套不一致判断。明确“详细讲/逐行/不懂/为什么”优先于默认简洁；纯代码/图片输入不默认要求用户再次确认全部内容，只有看不清/关键条件缺失才澄清。

deep_explain 至少包括任务与结果、必要概念、因果、中间状态、完整示例或对应原材料、边界/反例、代价及一个针对性自测；不是每题机械八标题。简单问题直接回答，不为单句常识启动检索、规划或多模型审稿。re_explain 必须保留正确前提，找出可能卡点，换例子/图景再解释并检验，不能把前文原样再说一遍。

首页、coach-qa、lesson、reading-chat、council 均按任务需要使用共享质量纪律，保留各自教学/阅读/决策差别。不能把全部业务都改成“代码逐行讲解”，也不能把“亲切/像真人”当正确性要求。

### Q02 上下文装配

最终发往 provider 的请求采用：稳定系统规则 → 当前模式与必要参数 → 本轮对象/版本 → 最新用户约束与关键学习事实 → 选中的历史 → 去重证据/工具结果 → 当前问题。稳定规则不包含每轮时间、临时对象或重复工具日志；公开过程记录不作为历史推理再注入。

优先保留：当前完整问题及所指代码、最新纠正、当前计划/书/章节的稳定 ID 与版本、用户显式目标/基础/每周时间、最近卡点。用户的纠正覆盖旧偏好，但保留来源和时间；“看过”不能自动变“掌握”。历史引用按数据处理，不能升级为新的指令。

近期对话按语义轮次保留，较早内容提取结构化事实/相关原文，不拼无界的每条 200 字摘录。对“上面代码/那个阶段”无法找到材料时，只询问缺失对象，不能猜。代码和题干不得静默从中间裁掉；超出模型可用窗口时明确要求拆分或选择材料，报告 context_overflow，不返回针对残缺代码的肯定结论。

预算以最终请求计算，含 system、tools schema、历史、附件估算、工具结果，不能只量用户文本。默认输入上限取模型可用窗口减输出预留，再与配置上限的较小值；初始建议 normal 6k、deep 12k 输入 token，输出预留 normal 1.2k、deep 6k，均可按真实模型窗口校准，绝非把这些建议当供应商硬规格。无 tokenizer 时用保守估算并标 estimated，运行时预算计入余量，不把字符数声称为真实 token。

证据按 ID/内容哈希去重；对象更新必须换版本/失效旧缓存。一次工具返回不同时完整存在 ctx、toolLog 和 tool 消息；保留引用链可追溯，禁止为了省 token 删除关键结论的证据。只读重复查询可在当前 run 内按签名缓存，写入后相关缓存失效；不得缓存批准结果或跨账户复用数据。

### Q03 内容保护与事实纪律

原始模型输出先通道分离，再只移除明确的工具协议/控制标记。合法英文标题、公式、代码注释、首尾结论不可因无汉字而删除。显示正文与可公开原文做差异测试，完整代码不可缺行；不允许模型谎称读过不存在的资料、完成未批准的操作或核验未跑过的结果。

阅读回答要绑定选中书/章节与材料，观点和事实分开；人生伙伴说明关键假设与可执行下一步，证据不足时不装确定。质量问题归因必须带实际请求快照与输出，不把所有失败推给模型、提示词或用户问题。

## 4. 首页滚动需求 S01–S06

S01 用户在首页历史位置提交有效消息后，当前会话滚到底部，恢复 following；仅空白输入、输入法 Enter 选词、失败校验不强制滚动。已有入口必须复用，不叠加 window.scrollTo。

S02 回底在新消息 DOM 已提交后执行；rAF 发起时捕获账户/会话/run/容器身份，执行时再核对。容器暂不存在时保留一次待处理 force，新容器出现后完成；组件卸载/账号切换清除旧帧。force 与普通跟随同帧排队时 force 优先，普通请求不能覆盖 force。

S03 流式输出中用户真实上滚立即暂停跟随，保留位置并显示“回到最新”；继续增量、展开过程、图片加载不能抢滚动权。用户点击回底、再次发送或主动滚到底部才恢复跟随。键盘、触屏、滚轮都要覆盖；程序滚动不冒充用户意图。

S04 首次发送没有消息容器也必须回底；AI 文本异步排版、表格/图片撑高时，在 following 模式内通过受控尺寸观察维持底部距离。每帧最多执行一次滚动写入，不在 token 回调内反复测量全页；监听器和 observer 卸载后为 0。

S05 A 会话发问后切到 B，A 的迟到 rAF、消息和过程均不能滚动 B；切回 A 按该会话保存的位置/跟随权恢复，不把所有会话都强制回底。跨账号不能复用位置。

S06 学习教练保持原阅读体验，不能因首页控制器改变讲义/课表滚动；任何页面不得由首页后台任务改 window 滚动。历史前十条之外应有真实“加载更早记录”入口，保持加载前后的可见锚点，不把提示文字当加载能力；这只扩展 UI 历史，不无限扩模型上下文。

## 5. 性能、兼容与数据

过程更新合并频率最多每 100ms 一次（终态/错误/审批立即提交）；每 run 最多 200 条过程事件、详情最多 800 字、可公开摘要累计最多 2k 字；达到上限保留首要证据与终态并标省略，不无界增长。正文按现有流式机制处理，不能与过程节流混淆而丢字。过程数据可随消息保存精简安全版本，序列化增加量每 run 建议不超过 32 KiB；旧消息无过程字段正常显示，无须清空用户历史。

不新增 UI 展示专用 provider 调用；不自动开圆桌/反思循环，不拉高工具轮数来掩盖回答质量。过程展示与摘要计算的 token 成本分别记录。已存在的同步/计量 P1 风险不能因本次 UI 完成被关闭；本轮不扩大这两项底层改造范围。
