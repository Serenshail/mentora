## 2. 验收层次与执行环境

1. 工具层：分别运行 `tsc --noEmit`、全项目 ESLint、相关运行时测试、全量测试与生产构建，保存 stdout/stderr 和真实 exit code。ESLint 现有警告必须报告，不通过改规则掩盖错误。
2. 运行时层：用实际 stream reader、受控时钟、rAF 队列、DOM 容器验证逻辑；不得只读源码搜关键字。现有源码锁可以补充，不能替代行为证据。
3. 浏览器层：1440×900、1024×768、390×844、320×700；首页、过程区、阅读历史、学习教练、阅读/圆桌入口。输入/停止/滚动用真实控件，记录测量与截图；模拟服务验证布局和错误路径，但不计真实质量通过。
4. 真实模型层：同 provider、model 版本、temperature、最大输出、工具与隔离初态；冻结配置后比较旧/新。演示模式、手写输出、模拟 API 不计质量成绩。模型不可用时记 BLOCKED，不能用界面通过顶替。

## 3. 回答评分：30 题、两个重复、成对比较

QUALITY-CASES 的每题固定输入、历史和期望；旧/新各执行两遍，共 120 次**主请求**。工具循环、内部重试、评分辅助模型仍算 provider 调用，不能藏在主请求数量外。案例顺序用固定 seed 交错旧/新，避免把供应商时段变化当改进。保留第一次运行结果，失败不得删题或只留最佳一次。

| 评分维度 | 分值 | 给满分的依据 |
| --- | --- | --- |
| 正确性与边界 | 25 | 所有关键事实、示例输出、边界均正确；程序例子可执行或可复核 |
| 解释与教学因果 | 25 | 对应题目的“为什么”和中间状态讲清，能支持独立操作；简答题用准确直接且无多余结构替代长讲要求 |
| 上下文与纠正 | 15 | 不重复询问已知约束，保留最新纠正，引用正确对象，不串会话 |
| 证据与不确定性 | 10 | 引用能定位、实际工具结果可对账，失败诚实，观点与事实分开 |
| 任务完成 / 行动边界 | 10 | 回答或动作符合意图，审批/取消/恢复正确；纯问答不产生多余写入 |
| 表达与排版 | 10 | 代码、术语、表格可读，没有私语/协议垃圾；长度服从用户问题 |
| 克制与资源使用 | 5 | 无不必要澄清、工具、重复请求或空洞长文 |

每维按 0/25%/50%/75%/100% 档评分，附原文片段和扣分理由；可精确分的客观项按逐条检查计分。关键事实错误、捏造执行成功/引用、未批准写入、跨账户串写任一发生即关键失败，整题不通过，不以平均分抵消。

正式通过要求：候选总体均分 ≥90/100；至少 27/30 题在**两次**运行中均 ≥85 且各自必需项齐全；七个维度总体各 ≥80%；关键失败为 0。候选不得在原已通过题引入关键退化。基线不足 90 不影响如实展示；候选未达标则继续修正并保留旧轮归档，再按相同题全量复测。

客观程序题由执行结果/索引状态比对；主观解释由实现者评分后交原主智能体盲复核，不给主智能体看“旧/新”标签直到分数锁定。主智能体必审全部失分/失败、所有行动题、全部参考样例题，并随机复核其余至少 30%。模型评分可辅助，不能自己给自己签通过，也不能把实现者的总分当独立复核。

## 4. Token 与费用门槛

质量与成本同时通过，不用节省 token 抵消关键错误。比较同一题、同一任务链的真实 provider 汇总：输入、输出、缓存、推理 token（如提供）、重试与工具后续轮；未返回 usage 的请求标 unknown，不能当 0。估算量与实际量分列，未能可靠计量时成本验收不通过，不伪造“省了 X%”。

候选总计费 token ≤基线 1.15 倍；normal/简答组 ≤1.05 倍；deep/re_explain 组 ≤1.25 倍；质量达标前基线错误/空答也必须保留，但不能用其异常低 token 直接得出公平的效率结论，须另报有效答题子集和全量两个口径。真实账单费用采用运行时官方单价配置，禁止把缓存 token 简单按未缓存价格或免费计算。

过程 UI 新增 provider 调用数必须为 0。全链路 p95 延迟不得比基线增加超过 15%；上游故障另报原始全量与成功子集，不能从总样本中删除。

评测脚本默认 dry-run，只检查配置、用例和预计上限，不调用模型。正式运行必须显式设置预算文件并使用已授权的模型账户；建议初始技术硬闸为 provider 调用最多 160 次、输入 1.2M、输出 360k token、并发 1、总时长 90 分钟。以上是待执行的预算上限，非供应商价格或已授权费用。预算文件还必须含明确的货币硬限额与价格版本；缺失或 unknown 超出保守预留时停止，不自动充值、换更贵模型或悄悄提高预算。先跑 4 个诊断题估计单题上界，再确认剩余题是否能在既定预算内完成；超限记预算中止，不记题目 PASS。

## 5. 滚动与过程客观门槛

- 发送 DOM 提交且容器可用后两帧内，scrollHeight − clientHeight − scrollTop ≤4px；提交前容器不存在也要在新容器可用两帧内完成。
- 用户向上操作后，接下来 20 个正文/过程增量不得抢回底部；记录锚点偏移，局部内容变化以外偏移 ≤4px。
- A→B 切换后等待 A 的已排队帧，B 滚动位置不变；相反方向、账号切换和卸载同测。
- 终态事件送达后 250ms 内 spinner 消失；60 秒内仅心跳时不得新增 60 个假步骤；不能把心跳当作业务进度重置等待提示。
- 1000 个分块中正文无丢字/重复；50 次展开收起不串会话；10 次切页后活动 listener/observer 数回到基线。
- 页面 scrollWidth ≤clientWidth+2px，宽表格/代码仅局部滚动；过程区不覆盖发送/停止/审批按钮。

## 6. 交付证据与主智能体复核

交付目录必须包含：实现提交/工作区哈希、文件清单、前后配置、实际请求组成清单（脱敏）、每题完整可公开正文、工具事件与副作用、usage、耗时、评分明细、失败原件、exit code、四宽度截图、浏览器测量 JSON、ACCEPTANCE.csv 实测结果。截图不得代替数据持久化/工具真实执行证据。

结果状态只有 PASS / FAIL / BLOCKED / NOT_RUN；失败分类为 PRODUCT、PROVIDER、HARNESS、BUDGET。HARNESS 修好后重新运行并保留旧档，不能把旧失败直接改 PASS。所有用例和基线哈希冻结，新增题另起版本；实现者不得在看到失败后放宽词数/删断言/改期望。

完成后由用户把交付目录或提交发回此主智能体。主智能体核对源码与配置差异、独立重跑关键用例、盲评正文、检查预算与副作用，输出逐项通过/未通过及修复清单。未有真实证据前，我方只确认“PRD 文档交付”，不预签产品通过。PRD 若有歧义或不可执行的条件，由主智能体修订并记录版本，不把责任笼统转给实现者。
